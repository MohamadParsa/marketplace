# کنترل تاریخ شمسی مشترک

`PersianDateField` برای مقدار controlled و `PersianDateInput` برای فرم uncontrolled است. `PersianDatesField` فهرست روزهای تعطیل را ویرایش می‌کند. هیچ وابستگی تقویمی جدیدی اضافه نشده است؛ تبدیل بر پایه تقویم Persian و منطقه زمانی `Asia/Tehran` در Intl است.

نمایش و ورود، شمسی با ارقام فارسی است؛ ورودی انگلیسی/عربی هم پذیرفته می‌شود. مقدار معتبر روزانه همان `YYYY-MM-DD` میلادی و مقدار زمان‌دار، ISO UTC است. برای `dateTime` ساعت تهران مبناست و timezone دستگاه دخالت ندارد. مقدار خالی اختیاری `""` است و مصرف‌کننده در قرارداد nullable آن را به null تبدیل می‌کند.

`name` خروجی hidden با مقدار API می‌سازد؛ input نمایشی نام قرارداد را ندارد. تاریخ نامعتبر **به مقدار خالی تبدیل نمی‌شود**: متن نامعتبر در state می‌ماند و customValidity فارسی دارد. فرم submit بومی آن را رد می‌کند؛ مصرف‌کننده‌ای که mutation را مستقیم از onClick اجرا می‌کند باید `validISODate` یا `validISOInstant` را هم کنترل کند. این رفتار مانع تبدیل اشتباه یک تاریخ نامعتبر به «بدون محدودیت» می‌شود.

تقویم داخل native dialog، انتخاب ماه/سال، جهت‌های صفحه‌کلید، Enter و Escape، min/max، پاک‌کردن، readonly و disabled دارد. رویداد close/cancel/Escape محصور است تا مودال میزبان بسته نشود. Date-only با ظهر ثابت تبدیل می‌شود و تاریخ روز با timezone دستگاه جابه‌جا نمی‌شود؛ ساعت‌های قدیمی تهران نیز از IANA محاسبه می‌شوند.

تست مشترک از cwd هر اپ با `npm run test:persian-dates` اجرا می‌شود؛ هر دو job CI آن را اجرا می‌کنند. [شواهد پیاده‌سازی و ممیزی کنترل‌ها](../../docs/delivery/order-lifecycle-review-2026-11-27/issue-141-verification.md).
