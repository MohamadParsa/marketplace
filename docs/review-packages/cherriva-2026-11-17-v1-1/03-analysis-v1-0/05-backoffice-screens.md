# نقشه منو، فرم و دسترسی پنل مشترک

نسخه: ۱.۰ | تاریخ: ۲۰۲۶-۱۱-۱۷ | وضعیت: تحلیل و طراحی برای بازبینی تیم فنی | مالک بررسی: محصول و راهبر فنی؛ انتساب شخص هنوز انجام نشده

## الگوی ساده پنل

یک shell مشترک شامل ناوبری، حساب، انتخاب فروشگاه فقط برای کاربر دارای اختیار، اعلان و breadcrumb. برای سلر، محدوده فروشگاه از نشست/عضویت می‌آید؛ dropdown یا query-string اختیار تازه نمی‌دهد. هر فهرست صفحه‌بندی، جست‌وجو، فیلتر وضعیت و دسترسی server-side دارد. فرم‌ها فیلدهای typed، خطای کنار فیلد، loading، خطای شبکه، تعارض نسخه و اخطار تغییر ذخیره‌نشده دارند. دکمه خطرناک دلیل و تأیید روشن می‌خواهد؛ ثبت audit جای آن را نمی‌گیرد.

کلیدهای مجوز زیر طراحی پیشنهادی برای رجیستری‌اند؛ قابلیت انتساب منو/فرم/عملیات و نقش سفارشی قطعی است. نقش‌های مدیر/کاتالوگ/مالی/پشتیبانی/سلر فقط preset پیشنهادی هستند؛ preset نباید مجوزهای جدید را خودکار به نقش سفارشی اضافه کند. مدیریت اختیار و ارتقای نقش نیازمند تصمیم CHQ-06 است.

## فلو نمونه فرم

فهرست مجاز → ایجاد/ویرایش draft → اعتبارسنجی frontend برای تجربه → اعتبارسنجی و مجوز سرور → پیش‌نمایش اثر → ثبت با نسخه → audit → انتشار مستقل در صورت نیاز → ابطال کش عمومی مرتبط. در conflict، مقدار جدید و انتخاب بازخوانی نشان داده شود؛ overwrite خاموش ممنوع.

ماتریس پیشنهادی سلر: offers/stock/shipping/supply/shipments و صورت‌حساب فقط فروشگاه خودش؛ ایجاد نقش، نرخ مشترک، کمیسیون مرکزی و اجرای refund/تسویه خارج از preset سلر. اختیار نرخ اختصاصی و تخفیف سلر هنوز CHQ-03/04 است و نباید از مالکیت فروشگاه نتیجه گرفته شود.

تسک‌های هر صفحه در [بک‌لاگ](tasks/README.md) مشخص‌اند. ساخت skeleton همه صفحات ممکن است؛ فعال‌کردن دکمه مالیِ وابسته به تصمیم باز مجاز نیست. مالی و سفارش با fixtureهای ایزوله تست می‌شوند، نه فرم ساخت سفارش واقعی خارج از دامنه.
