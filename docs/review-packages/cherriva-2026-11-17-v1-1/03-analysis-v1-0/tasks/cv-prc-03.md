# CV-PRC-03 — نرخ طلا مشترک و اختصاصی سلر

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend قیمت‌گذاری + محصول/مالی؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

یک سلر از نرخ چریوا و دیگری از نرخ خودش استفاده کند.

## دامنه و راه‌حل فنی

GoldRate version/source/seller/type/unit/purity/validity و rate selection فروشگاه؛ فرم ثبت و preview منبع. تاریخچه نرخ استفاده‌شده حفظ و نبود نرخ خطای صریح؛ دریافت خودکار نرخ الزام نیست.

محل تجربه: **BO-10**. مرجع طراحی: [06-catalog-pricing.md](../06-catalog-pricing.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-PRC-03-AC01: دو سلر منابع متفاوت مستقل مصرف کنند.
- CV-PRC-03-AC02: نرخ اختصاصی مفقود با نرخ سلر دیگر یا مشترک خاموش جایگزین نشود.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **واحد ناسازگار، صفر صریح، نرخ منقضی، وراثت غلط و snapshot قدیمی**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
