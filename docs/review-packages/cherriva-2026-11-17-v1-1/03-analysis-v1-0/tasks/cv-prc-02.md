# CV-PRC-02 — مارکاپ دسته با وراثت و صفر صریح

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend قیمت‌گذاری + محصول/مالی؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

قاعده دسته مثل طلا بر درصد پیش‌فرض مقدم و قابل توضیح باشد.

## دامنه و راه‌حل فنی

CategoryMarkup method+category با version؛ resolver دسته مستقیم تا root اولین رکورد را می‌گیرد و fallback default؛ preview source path؛ unique constraint. صفر ثبت‌شده با null فرق دارد.

محل تجربه: **BO-13**. مرجع طراحی: [06-catalog-pricing.md](../06-catalog-pricing.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-PRC-02-AC01: طلا۶/شمش۵/default۳ نتیجه شمش۵ بدهد و بدون شمش نتیجه۶.
- CV-PRC-02-AC02: شمش صفر روی والد۶ مقدم باشد و روش فروش دیگر اثر نگیرد.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **واحد ناسازگار، صفر صریح، نرخ منقضی، وراثت غلط و snapshot قدیمی**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
