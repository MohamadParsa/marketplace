# CV-CAT-08 — انتشار و بررسی محصول/خصوصیت

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

کیفیت محتوا کنترل شود و تغییر قیمت بی‌دلیل منتظر بررسی نماند.

## دامنه و راه‌حل فنی

صف draft/review/published/rejected با reason/version؛ publication policy فروشگاه؛ approve/reject جدا از edit. بازبینی محتوای جدید نسخه قبلی public را نگه دارد؛ event ابطال کش.

محل تجربه: **BO-07/08 بررسی**. مرجع طراحی: [05-backoffice-screens.md](../05-backoffice-screens.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-CAT-08-AC01: منتشرکردن بدون publish permission رد شود.
- CV-CAT-08-AC02: تغییر فقط موجودی عرضه وارد صف ویرایش متن نشود.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **ترکیب/مرجع نامعتبر، داده خارج scope، ناموجودی و تغییر هم‌زمان**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
