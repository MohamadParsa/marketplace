# CV-WEB-10 — نتیجه پرداخت و پیگیری تلاش

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: frontend سایت + backend قرارداد مربوط؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

کاربر وضعیت نامعلوم را با شکست یا موفقیت اشتباه نگیرد.

## دامنه و راه‌حل فنی

چهار view موفق قطعی/ناموفق/unknown/شارژ موفق بدون سفارش؛ poll محدود همان attempt و شناسه پیگیری؛ back/reload بدون submit جدید. receipt سفارش فقط از paid سروری.

محل تجربه: **Payment result**. مرجع طراحی: [08-storefront-design.md](../08-storefront-design.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-WEB-10-AC01: redirect مرورگر به‌تنهایی success نشان ندهد.
- CV-WEB-10-AC02: unknown دعوت به پرداخت تازه نکند و شارژ دیررس رسید سفارش نسازد.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **خالی/خطا/بازگشت مرورگر، viewport موبایل/دسکتاپ، keyboard و انتخاب نامشخص**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
