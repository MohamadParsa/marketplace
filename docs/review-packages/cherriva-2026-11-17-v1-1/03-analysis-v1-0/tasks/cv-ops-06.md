# CV-OPS-06 — برآورد و محاسبه مجدد هزینه حمل

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend سفارش + frontend پنل + عملیات؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

هزینه و زمان با اقلام/شهر و لغو جزئی درست بمانند.

## دامنه و راه‌حل فنی

shipping quote با snapshot و business calendar؛ آماده‌سازی/حمل/دریافت جدا. پس از لغو فقط اختلاف هنوز نگه‌داشته‌شده refund؛ افزایش محاسبه جدید هزینه پلتفرم، نه مبلغ اضافه مشتری.

محل تجربه: **BO-17 preview / Checkout**. مرجع طراحی: [09-order-shipping.md](../09-order-shipping.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-OPS-06-AC01: پنج‌شنبه/جمعه و تعطیلات از آماده‌سازی حذف شوند.
- CV-OPS-06-AC02: دو لغو پیاپی حمل اولیه را دوبار refund نکنند.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **مقدار بیش‌ازقلم، اقدام نامجاز، مهلت گذشته و رقابت لغو/اعزام**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
