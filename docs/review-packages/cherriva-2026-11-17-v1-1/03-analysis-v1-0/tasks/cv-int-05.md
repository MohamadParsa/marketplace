# CV-INT-05 — فضای رسانه و تحویل asset واقعی

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend integration + DevOps/عملیات؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

تصویرها پایدار، امن و سریع تحویل شوند.

## دامنه و راه‌حل فنی

object storage adapter، اندازه‌های responsive، upload validation و دسترسی private برای مدارک؛ public assets با hash/CDN؛ lifecycle و backup reference. URL مدارک سلر عمومی نشود.

محل تجربه: **Media storage / CDN**. مرجع طراحی: [11-quality-operations.md](../11-quality-operations.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-INT-05-AC01: نسخه تصویر جدید بدون cache قدیمی نمایش یابد.
- CV-INT-05-AC02: آدرس مدارک خصوصی بدون مجوز دانلود نشود.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **timeout، callback جعلی/دیررس/تکراری و نبود قابلیت provider**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
