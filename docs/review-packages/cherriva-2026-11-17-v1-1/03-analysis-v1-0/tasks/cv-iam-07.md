# CV-IAM-07 — اطلاعات مشتری و نشانی‌های گیرنده

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

مشتری چند آدرس داشته باشد و گیرنده با صاحب حساب اشتباه نشود.

## دامنه و راه‌حل فنی

API خصوصی پروفایل و address CRUD با نام/شماره گیرنده، استان/شهر، کدپستی و متن؛ validation و ownership؛ تغییر شماره ورود با احراز مجدد. گیرنده حساب login جدید ایجاد نکند.

محل تجربه: **Profile / Address**. مرجع طراحی: [08-storefront-design.md](../08-storefront-design.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-IAM-07-AC01: ویرایش آدرس دیگری با تغییر ID رد شود.
- CV-IAM-07-AC02: تغییر گیرنده شماره ورود و مالک خرید را تغییر ندهد.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **درخواست مستقیم بدون مجوز، تغییر شناسه فروشگاه، نشست منقضی و ابطال نقش**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.

شناسه تسک، فایل‌های تغییرکرده، رفتار حاصل، نتیجه بررسی‌ها با شاهد، قرارداد مؤثر و مانع باقی‌مانده؛ طبق [فرمت تحویل](../16-agent-delivery.md). همه تسک‌ها در این نسخه todo هستند؛ تهیه سند به معنی شروع یا اتمام کدنویسی نیست.
