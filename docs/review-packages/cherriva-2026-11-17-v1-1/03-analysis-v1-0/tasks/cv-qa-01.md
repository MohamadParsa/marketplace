# CV-QA-01 — آزمون مجوز، IDOR و داده خصوصی

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: QA + مالک ماژول + محصول؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

پنل مشترک و دسترسی نقش سفارشی نشت داده یا ارتقای اختیار نسازند.

## دامنه و راه‌حل فنی

ماتریس نقش×عملیات×فروشگاه×وضعیت با API مستقیم، export و رسانه؛ نقش revokeشده، کاربر read-only و سلر قبل/بعد تأمین؛ CSRF و unknown key. test منفی از منوی UI مستقل باشد.

محل تجربه: **تمام پنل و export**. مرجع طراحی: [11-quality-operations.md](../11-quality-operations.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-QA-01-AC02: پیش از تأمین اطلاعات گیرنده از پاسخ حذف و بعد revoke عملیات قبلی رد شود.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **تفکیک fixture از sandbox و پذیرش واقعی؛ شواهد قابل تکرار**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
