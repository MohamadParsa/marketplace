# CV-CAT-10 — سنجه بازدید و فروش برای مرتب‌سازی

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

مرتب‌سازی پربازدید/پرفروش از داده واقعی و قابل توضیح ساخته شود.

## دامنه و راه‌حل فنی

aggregate روزانه بازدید معتبر و فروش قطعی با بازه configurable و job idempotent؛ baseline صفر برای داده آزمون؛ duplicate view suppression و عدم ثبت PII. snapshot/تعریف refund از قرارداد سنجه پیروی کند.

محل تجربه: **BO تنظیمات / PLP sorts**. مرجع طراحی: [06-catalog-pricing.md](../06-catalog-pricing.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-CAT-10-AC01: rerun job شمار فروش را دوبار زیاد نکند.
- CV-CAT-10-AC02: ربات/refresh تکراری طبق policy مصوب رتبه ساختگی نسازند و ناموجودها انتهای نتایج بمانند.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **ترکیب/مرجع نامعتبر، داده خارج scope، ناموجودی و تغییر هم‌زمان**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
