# CV-CMS-05 — زمان‌بندی و بازگشت نسخه محتوا

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend محتوا + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

در صورت نیاز کمپین انتشار و پایان زمان‌دار کنترل شود.

## دامنه و راه‌حل فنی

valid_from/to و scheduler با timezone؛ rollback نسخه تازه بسازد. خاموش‌کردن سکشن و ابطال تخفیف مالی دو عملیات مستقل باشند.

محل تجربه: **BO-16 schedule**. مرجع طراحی: [07-content-sections.md](../07-content-sections.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-CMS-05-AC01: پایان بازه خروجی public و cache را تازه کند.
- CV-CMS-05-AC02: rollback سابقه را پاک نکند.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **draft در برابر public، config نامعتبر، لینک ناامن و conflict انتشار**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
