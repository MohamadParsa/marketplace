# CV-WEB-09 — پرداخت، روش فروش و جلسه زمان‌دار

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: frontend سایت + backend قرارداد مربوط؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

مشتری تفاوت نقدی/اعتباری و مبلغ نهایی را آگاهانه بپذیرد.

## دامنه و راه‌حل فنی

انتخاب روش واجد شرایط و نمایش breakdown markup پس از تخفیف/ارسال جدا؛ نقدی balance/deficit/topup و debit کل، BNPL مستقل. countdown از server و expired→cart؛ controls duplicate-safe.

محل تجربه: **Checkout payment**. مرجع طراحی: [08-storefront-design.md](../08-storefront-design.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-WEB-09-AC01: تغییر روش جمع واقعی سرور را قبل تعهد نشان دهد.
- CV-WEB-09-AC02: انقضا اقدام تازه را رد و BNPL با شارژ wallet ترکیب نشود.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **خالی/خطا/بازگشت مرورگر، viewport موبایل/دسکتاپ، keyboard و انتخاب نامشخص**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
