# CV-IAM-04 — کاربر، انتساب نقش و ابطال اختیار

وضعیت تحلیل: بخش وابسته مسدود / بخش مستقل قابل شروع. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

اختیار اشخاص قابل مدیریت و تغییرش بلافاصله مؤثر باشد.

## دامنه و راه‌حل فنی

role grant با scope، نسخه و audit؛ غیرفعال‌سازی حساب و محافظ آخرین مدیر؛ API اختیار جاری را بازخوانی کند. مسیر assignment از policy صریح استفاده کند، نه قبول role_id از کاربر عادی.

محل تجربه: **BO-02**. مرجع طراحی: [05-backoffice-screens.md](../05-backoffice-screens.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-IAM-04-AC01: بعد از حذف grant، نشست قدیمی عملیات قبلی را انجام ندهد.
- CV-IAM-04-AC02: کاربر نتواند به خودش نقش بالاتر یا فروشگاه دیگر انتساب دهد.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **درخواست مستقیم بدون مجوز، تغییر شناسه فروشگاه، نشست منقضی و ابطال نقش**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
