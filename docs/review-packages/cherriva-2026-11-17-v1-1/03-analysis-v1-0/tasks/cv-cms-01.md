# CV-CMS-01 — مدل Page و سکشن‌های typed

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend محتوا + frontend پنل؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

صفحه اصلی و لندینگ بدون CMS پیچیده قابل چیدمان باشند.

## دامنه و راه‌حل فنی

Page scope/key و Section type/config/order/enabled/revision؛ هشت نوع محدود سند۰۷؛ source category/promotion/manual؛ validation مرکزی و بدون SQL یا widget code دلخواه.

محل تجربه: **BO-16**. مرجع طراحی: [07-content-sections.md](../07-content-sections.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-CMS-01-AC01: صفحه چند سکشن با ترتیب پایدار ذخیره شود.
- CV-CMS-01-AC02: config نامعتبر، scope خارج اختیار و type ناشناخته رد شوند.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **draft در برابر public، config نامعتبر، لینک ناامن و conflict انتشار**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
