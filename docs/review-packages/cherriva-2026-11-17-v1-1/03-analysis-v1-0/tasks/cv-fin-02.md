# CV-FIN-02 — شارژ مستقل و شارژ کسری خرید

وضعیت تحلیل: دامنه پایه روشن؛ اجرای پس از وابستگی‌ها. مبنای بیزینسی از [تصمیم‌ها](../01-scope-decisions.md)؛ مسیر فنی پیشنهاد این بسته است. مسئول پیشنهادی: backend مالی + frontend پنل + مالی؛ انتساب فرد/موعد انجام نشده است.

## هدف بیزینسی

مشتری دلخواه یا بیش از کسری شارژ کند و پولش گم نشود.

## دامنه و راه‌حل فنی

attempt purpose=topup، adapter آزمون و verify؛ credit wallet یک‌باره با lot؛ checkout اختیاری. success دیررس credit می‌دهد ولی سفارش نه؛ BNPL topup ممنوع.

محل تجربه: **Topup API / fixture**. مرجع طراحی: [10-finance.md](../10-finance.md)؛ قرارداد عملیات و خطا: [API](../04-api-contracts.md). فقط منابع و عملیات همین تسک در دامنه تغییرند؛ قابلیت جدید نامرتبط یا پاسخ CHQ به‌صورت حدسی اضافه نشود.

## ترتیب انجام و خروجی

1. وابستگی‌های زیر و سؤال‌های همین مسیر را کنترل؛ DTO/ورودی/خروجی، permission و شرط وضعیت مرتبط را از قرارداد استخراج کنید.
2. use case/adapter یا component محدود طبق راه‌حل بالا بسازید؛ تغییر داده با نسخه و عملیات تکرارشونده با کلید یکتا کنترل شوند. برای task رابط کم‌خطر کنترل‌های نامرتبط مالی اضافه نکنید.
3. معیارهای زیر را با داده ساختگی بررسی و خروجی قابل بازبینی شامل کد/قرارداد لازم، تست متناسب و گزارش تحویل بدهید. schema یا API جدید باید با مصرف‌کننده هماهنگ باشد.

## معیار پذیرش

- CV-FIN-02-AC01: callback دوباره فقط یک credit داشته باشد.
- CV-FIN-02-AC02: شارژ دیررس/مازاد در wallet بماند و خرید ناسازگار خودکار نسازد.

## مجوز، خطا و بررسی

قواعد نقش/فرم/عملیات سند پنل و scoped DTO سند معماری در تمام دسترسی‌های مرتبط اعمال شوند. بررسی معنادار این گروه: **اثر مالی تکراری، منفی‌شدن available، تراز ledger و unknown**. برای عملیات سرور، پذیرش‌های مثبت/منفی مرتبط با DB/adapter آزمون بررسی شوند؛ برای ظاهر، مرور بصری و تعاملی متناسب کافی است و تست تقلیدی لازم نیست. نوع و نتیجه هر بررسی در گزارش ثبت شود؛ این فایل خود گزارش آزمون نیست.
