# CV-R2-12 — پذیرش اصلاحات، ردیابی و آماده‌سازی تحویل

## هدف بیزینسی

تیم بداند چه چیزی طراحی شده، چه چیزی ساخته/آزموده شده و چه چیزی هنوز تصمیم لازم دارد.

این کار اصلاح/تکمیل تسک‌های CV-QA-01، CV-QA-04، CV-QA-06 است؛ قابلیت مستقل تکراری یا پیاده‌سازی انجام‌شده محسوب نشود. قواعد صریح را از [مشخصات جاری](../README-fa.md) و راه‌حل پیشنهادی را از متن زیر بخوانید.

## دامنه و راه‌حل فنی پیشنهادی

ماتریس rule→spec→task→screen→evidence؛ contract tests برای scope/credential/lead و browser برای binding/section/checkout. گزارش mock، integration، browser و provider جدا؛ اصلاح تسک اصلی به‌جای دوباره‌شمردن قابلیت‌ها.

## داده و قرارداد پیشنهادی

test fixtures بدون اطلاعات شخصی؛ snapshot قرارداد و گزارش قابل بازتولید، هیچ provider واقعی در این task لازم نیست.

نام endpoint و schema در این سند پیشنهاد قرارداد است؛ در kickoff با OpenAPI پروژه مقصد هماهنگ شود و بدون نسخه‌گذاری با مسیر قدیمی موازی نشود.

## دسترسی و محدوده

بازبین مشخص برای محصول/فنی؛ test runner مجوز production یا انتقال وجه ندارد.

## خطا و حالات رابط

شکست تست مانع همان مسیر؛ broken link/شناسه تکراری/گم‌شدن نیازمندی رد تحویل.

حالت loading، خالی، خطای شبکه و تلاش مجدد امن، عدم دسترسی و conflict متناسب با همان عملیات لازم‌اند. خطا نباید draft معتبر کاربر را حذف یا موفقیت ساختگی اعلام کند.
