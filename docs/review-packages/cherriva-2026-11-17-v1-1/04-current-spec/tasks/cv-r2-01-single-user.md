# CV-R2-01 — هویت واحد و عضویت چندمنظوره

## هدف بیزینسی

خریدار و همکار پنل و عضو فروشگاه، بدون ایجاد حساب تکراری از یک هویت استفاده کنند.

این کار اصلاح/تکمیل تسک‌های CV-IAM-04، CV-IAM-05، CV-IAM-07 است؛ قابلیت مستقل تکراری یا پیاده‌سازی انجام‌شده محسوب نشود. قواعد صریح را از [مشخصات جاری](../identity-auth-fa.md) و راه‌حل پیشنهادی را از متن زیر بخوانید.

## دامنه و راه‌حل فنی پیشنهادی

User مرجع هویت؛ RoleAssignment و StoreMembership رابطه مستقل؛ buyer/customer فقط کاربرد User. Store و آدرس گیرنده مستقل باقی بمانند. موبایل نرمال یکتا؛ سیاست ایمیل در کار بعد. اگر داده قدیمی واقعی وجود داشت، گزارش تکراری‌ها قبل از merge، بدون ادغام خودکار.

## داده و قرارداد پیشنهادی

User، RoleAssignment، StoreMembership؛ GET /me و GET /admin/users/:id، DTO بدون credential.

نام endpoint و schema در این سند پیشنهاد قرارداد است؛ در kickoff با OpenAPI پروژه مقصد هماهنگ شود و بدون نسخه‌گذاری با مسیر قدیمی موازی نشود.

## دسترسی و محدوده

users.view/edit و members.manage در scope مجاز؛ داشتن کاربرد خریدار، مجوز پنل ایجاد نمی‌کند.

## خطا و حالات رابط

شناسه ناموجود 404؛ دسترسی خارج scope 403 یا 404 طبق قرارداد مشترک؛ تعارض نسخه409.

حالت loading، خالی، خطای شبکه و تلاش مجدد امن، عدم دسترسی و conflict متناسب با همان عملیات لازم‌اند. خطا نباید draft معتبر کاربر را حذف یا موفقیت ساختگی اعلام کند.
