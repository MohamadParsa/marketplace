# BO-23 — تسویه فروشندگان

شناسه سند: CVBO-BO-23 | نسخه: ۰.۱ | تاریخ: ۲۰۲۶-۱۱-۱۷ | وضعیت: in-review | مالک تصمیم: الیاس؛ بازبین فنی پیشنهادی: راهبر فنی، انتساب شخص باز

## هدف بیزینسی

تخصیص قلمی، مانده قابل تسویه و بدهی‌های قابل پیگیری. این فرم باید اقدام بعدی و محدوده مسئولیت را روشن کند؛ ظاهر فرم جای تصمیم باز یا اجازه اجرای عملیات نیست.

## داده و فیلدهای تحلیل

سلر، اقلام، سهم، بدهی، مبلغ ناخالص/خالص، مرجع انتقال

## مسیر اصلی

فروشگاه مجاز → صورت‌حساب قلمی → سهم قرارداد/بدهی → تخصیص → انتقال → شاهد؛ عدد نمونه اثبات محاسبه یا واریز نیست.

## دسترسی

عملیات پیشنهادی رجیستری: settlements.view/create/execute

نمای نقش‌های نمونه: مدیر کل، فروشنده، مالی. نقش‌های نمونه تعیین نهایی اختیار نیستند. هر عملیات سمت سرور مجوز مستقل می‌خواهد؛ سلر فقط فروشگاه منتسب، نه scope ارسالی دلخواه کلاینت.

## اعتبارسنجی و حالات

تخصیص قلمی؛ پرداخت تکراری ممنوع؛ ثبت مرجع ≠ واریز موفق

loading، empty، error و forbidden از نوار بررسی قابل مشاهده‌اند. جست‌وجو و وضعیت روی فهرست‌های جدول‌دار فعال‌اند. در محصول خطای اعتبارسنجی، conflict و retry امن به فرم متصل شوند؛ این نمونه همه قراردادهای backend را اجرا نمی‌کند.

## پذیرش پیشنهادی تیم

- مسیر اصلی بالا با داده آزمون و نقش مجاز قابل تکمیل باشد؛ داده یا عملیات خارج scope نمایش و اجرا نشود.
- قواعد و محدودیت‌های همین صفحه و [مرجع تحلیل](../references/backoffice-analysis-fa.md) در API و UI یکسان باشند.
- خطا و داده خالی قابل فهم باشند؛ متن طولانی، رقم فارسی و نمای موبایل آزمون شوند.
