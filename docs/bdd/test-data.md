# داده آزمون مشترک BDD

این داده‌ها کاملاً ساختگی‌اند و فقط برای سناریوهای مستندات استفاده می‌شوند. در اجرای آینده، هر محیط باید نسخه مستقل و قابل پاک‌سازی از همین نقش‌ها و موجودیت‌ها بسازد.

## بازیگران

| شناسه | نقش | توضیح |
| --- | --- | --- |
| `USR-CUST-001` | مشتری | مشتری نمونه با کیف پول و دو آدرس ساختگی |
| `USR-CUST-002` | مشتری | مشتری نمونه بدون سابقه پرداخت |
| `USR-SELLER-A` | فروشنده | عضو مجاز فروشگاه الف |
| `USR-SELLER-B` | فروشنده | عضو مجاز فروشگاه ب |
| `USR-BO-SUPPORT` | کاربر بک‌آفیس | مجاز به رسیدگی پشتیبانی |
| `USR-BO-FINANCE` | کاربر بک‌آفیس | مجاز به عملیات مالی |
| `USR-BO-READONLY` | کاربر بک‌آفیس | فقط خواندن؛ بدون مجوز تغییر |

| شناسه | نوع | مقدار آزمون |
| --- | --- | --- |
| `STORE-A` / `STORE-B` | فروشگاه | دو فروشگاه مستقل با محدوده ارسال داخل ایران |
| `PROD-TEA-001` | محصول مشترک | چای نمونه با ترکیب‌های ازپیش‌تعریف‌شده |
| `PROD-PHONE-001` | محصول مستقل | گوشی نمونه با موجودی محدود |
| `VAR-BLACK-001` | ترکیب | رنگ مشکی، تعداد واحدی؛ وزن آزاد ندارد |
| `OFFER-A-001` / `OFFER-B-001` | پیشنهاد فروش | یک ترکیب یکسان با قیمت و موجودی مستقل |
| `ORDER-MULTI-001` | خرید | خرید دوفروشگاهی برای سناریوهای تأمین و ارسال |
| `SESSION-EXPIRED-001` | جلسه پرداخت | جلسه منقضی‌شده با رزرو آزادشده |
| `WALLET-001` | کیف پول | گردش شامل شارژ، مصرف و مانده قابل ردیابی |
| `REFUND-001` | بازپرداخت | بازپرداخت جزئی یک قلم با منشأ پرداخت مشخص |

| `OTP-001` | نشست هویت | کد ساختگی با اعتبار ۹۰ ثانیه، سقف ۵ تلاش در یک ساعت و فاصله ارسال مجدد ۶۰ ثانیه |

## اصول داده‌سازی

- شماره تلفن، کدپستی، نشانی، کد رهگیری و شناسه پرداخت باید غیرواقعی و مخصوص محیط آزمون باشند.
- داده‌ها باید سناریوهای چندفروشگاهی، کمبود موجودی، عدم تأمین، تأمین جایگزین، پرداخت نامشخص، refund و بدهی پس از تسویه را پوشش دهند.
- داده آزمون نباید انتخاب ارائه‌دهنده واقعی، واحد ذخیره درگاه، مقررات کشور یا قانون حل‌نشده `Q-*` را جعل کند.
- هر اجرای سناریو باید داده‌های خود را ایزوله کند تا تکرار اجرای یک سناریو نتیجه سناریوی دیگر را تغییر ندهد.


## داده پیشنهادی سناریوهای محتوای کاتالوگ

برای CV-R2-16/17 دو دسته ساختگی «دسته آزمایشی الف / Sample A» و «دسته آزمایشی ب / Sample B» با والد، آیکن و خصوصیت مستقل و دو محصول آزمون با برند آزمایشی در نظر گرفته شوند. عنوان/کلمات/توضیح متا برای هر رکورد متفاوت، یک محصول مشترک با دو عرضه متعلق به دو فروشگاه و موجودی رزروشده باشد. فایل‌های گالری تولیدشده و فاقد اطلاعات واقعی باشند. طول/واحد/سیاست انتشار/پیش‌فرض از قرارداد منتخب پس از پاسخ پرسش‌ها بیایند؛ این بخش fixture اجرایی یا داده تولیدشده موجود نیست.


## داده پیشنهادی انتشار اولیه

چهار دسته ساختگی موبایل/هندزفری/پاوربانک/ساعت هوشمند، کالاهای منتشرشده موجود/ناموجود و draft، دو فروشگاه با عرضه مستقل، یک محصول دو تنوع و یک عرضه با آخرین موجودی برای آزمون هم‌زمانی تعریف شوند. مشتری آزمون دو آدرس و یک کیف پول با گردش شارژ/مصرف قابل ردیابی داشته باشد. اعلام واریز فقط با مدرک تولیدشده ساختگی، مقصد غیرواقعی و تأیید شبیه‌سازی‌شده توسط نقش مجاز در محیط آزمون انجام شود؛ اطلاعات بانک یا کارت واقعی در fixture ثبت نشود. انقضا و مبلغ متفاوت پس از انتخاب LCH-Q02 تا04 fixture شوند؛ تنظیم محیط عمومی از این fixture استخراج نشود. هیچ‌کدام داده اجرایی موجود یا تراکنش بانکی انجام‌شده نیستند.
