## رفتار مشترک پیشنهادی برای بررسی

این بخش مرجع مشترک حالت‌های رابط است؛ هر قابلیت فقط استثناهای خودش را اضافه می‌کند.

| حالت | رفتار مورد انتظار |
| --- | --- |
| بارگذاری | وضعیت روشن؛ عملیات مالی/مخرب تکرارپذیر نشود |
| خالی | تفاوت «هیچ داده‌ای نیست» و «فیلتر نتیجه ندارد» مشخص و اقدام مناسب ارائه شود |
| خطای ورودی | پیام کنار فیلد، حفظ ورودی معتبر و تمرکز قابل دسترس |
| خطای شبکه | حفظ داده فرم/سبد؛ در عملیات مالی ابتدا وضعیت قبلی بررسی شود، نه پرداخت مجدد کورکورانه |
| دسترسی غیرمجاز | عملیات مسدود و پیام متناسب؛ داده حساس در پاسخ یا cache باقی نماند |
| تعارض نسخه/موجودی | تغییر واقعی و اقدام بازبینی به کاربر نمایش داده شود |
| موفقیت | نتیجه قابل پیگیری نمایش داده شود؛ پیام موفقیت جای تأیید سروری نیست |

رفتار صفحه‌کلید، مدیریت فوکوس مودال، بازگشت مرورگر، RTL و چیدمان موبایل در طراحی هر مسیر ارزیابی شود. این‌ها پیشنهاد طراحی‌اند؛ زبان، استاندارد و مرورگر هدف در Q-007/Q-008 نهایی می‌شود.

نام صفحه‌ها در این اسناد مفهومی است؛ URL قطعی، layout گرافیکی و نام endpoint تعیین نشده‌اند. مرجع سناریوهای مشترک در حوزه است؛ سناریوهای این بخش تعامل قابل مشاهده را پوشش می‌دهند.
