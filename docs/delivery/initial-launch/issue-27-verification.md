## رفتار حاصل و محدوده

خانه React از API واقعی Go تغذیه می‌شود: بنر اصلی دو اندازه، میان‌بر تمام دسته‌های دارای کالای قابل خرید، تخفیف ویژه واقعی، چهار کروسل موبایل/هندزفری/پاوربانک/ساعت هوشمند، دو بنر مکمل و فوتر. انتخاب عرضه کمترین قیمت نقدی نهاییِ ثبت‌شده بدون ارسال، سپس تأمین سریع‌تر و شناسه ثابت است. کارت خرید سریع یا انتخاب تنوع ندارد. ناموجود، پیش‌نویس، دسته منتشرنشده و فروشنده غیرفعال به خانه نمی‌رسند؛ ریل کم‌کالا تکرار مصنوعی نمی‌سازد.

بک‌آفیس `/home-catalog` ایجاد/ویرایش دسته، برند، محصول و انتشار حداقلی (شامل اکشن قدیمی انتشار)، تصویر اصلی، دسترسی سریع به تنوع/عرضه/قیمت/موجودی و نگاشت چهار ریل را دارد. فرم بنر موجود با جایگاه hero/promo استفاده می‌شود. قاب پنل، ورود، داشبورد و فرم‌های این مسیر با طرح **A — متعادل و شیک**، وزیرمتن و هویت گیلاسی تطبیق داده شدند؛ این ادعای تکمیل بازطراحی همه فرم‌های آینده پنل نیست.

[قرارداد مدل، API، مجوز، خطا، کش و رسانه](../../architecture/contracts/homepage-launch.md) · [قاعده نهایی ورود](../../decisions/adr-008-shared-login-modes.md)

ایمیل فقط با رمز و موبایل با انتخاب رمز یا OTP وارد می‌شود؛ انتخاب روش رمز پیامک نمی‌فرستد. API این قاعده را در بک‌آفیس و سایت روی یک User اجرا می‌کند؛ UI ورود بک‌آفیس و پروفایل تعریف ایمیل/رمز در این تحویل است. رابط حساب مشتری همچنان #30 است. OTP ایمیلی برای ورود اضافه نشده است.

## بررسی‌های اجراشده

- `go test -json ./...`: **۹۶ تست/زیرتست موفق**، بدون شکست؛ PostgreSQL جداگانه فعال بود و دو تست پایداری skip نشدند.
- `go vet ./...`: موفق. `go test -race` محلی اجرا نشد؛ ابزار CGO ویندوز موجود نیست و CI لینوکس نتیجه جدا دارد.
- lint/build بک‌آفیس، storefront، seller-portal و packages/contracts: موفق. هشدار اندازه bundle بک‌آفیس غیرمسدودکننده باقی است.
- Playwright CLI: **۲۷/۲۷ بررسی موفق**، صفر runtime pageerror. رد عمدی فایل با400، abort تصویر و پاسخ503 جزو آزمون‌های منفی‌اند؛ ادعای نبود همه خطاهای شبکه/console نمی‌شود.
- بعد از آخرین تغییر صرفاً متنی هشدار داشبورد، lint/build پنل تکرار و تصویر داشبورد تازه تهیه شد؛ منطق ۲۷ بررسی تغییر نکرد.
- داده عمومی خانه/بنر پیش و پس از restart واقعی API یکسان ماند؛ تصویر و ورود رمز حساب محلی نیز پس از restart تأیید شدند.
- [خروجی ماشین‌خوان](issue-27-checks.json) از نتایج واقعی Go و مرورگر استخراج شده است. [سناریوهای BDD](../../bdd/features/experiences/initial-launch.feature) معیار مستند هستند؛ runner مستقل Gherkin اجرا نشده است.
- manifest تاریخی۶۶۴ فایل با SHA256 خام یا نسخه LF بررسی شد؛ هیچ فایل بسته طراحی تغییر نکرده است. کنترل لینک‌ها، شناسه‌ها، وضعیت و `git diff --check` در تحویل انجام شد.

## تکرار اجرا و تحویل به پارسا

1. شاخه این کار، شاخه برنامه انتشار و شاخه ورود/هویت پارسا را یکپارچه می‌کند؛ PRهای #20/#21 و زنجیره کاتالوگ وابستگی‌اند. این merge در feature انجام شده و main/deploy تغییر نکرده است.
2. برای دیتابیس جداگانه local/test، migrationهای `000001` و `000002` با ابزار `apps/api/cmd/migrate` اعمال شوند. طبق [راهنمای repository بررسی](../../architecture/contracts/backoffice-review.md)، REVIEW_DATABASE_URL و APP_ENV=test تنظیم شوند. حالت بدون URL حافظه‌ای است و داده‌اش پایدار نیست.
3. `npm ci` و lint/build در دو app وب؛ API با `PORT=8098 WEB_ROOT=../backoffice-web/build` از apps/api اجرا شود. storefront با `CHERRIVA_API_PROXY=http://localhost:8098` و Vite روی5197 اجرا شود. API:8098 بک‌آفیس ساخته‌شده را سرو می‌کند.
4. فقط در دیتابیس ایزوله: `node tests/e2e/seed-home.cjs http://127.0.0.1:8098` و سپس `playwright-cli -s=cherriva-home run-code --filename tests/e2e/homepage.cjs`. fixture ورود مرورگر باید طبق حساب ساختگی داخل اسکریپت، با API پروفایل همان محیط آماده شود؛ این اسکریپت ابزار ساخت ادمین واقعی نیست.
5. روی سیستم فعلی دیتابیس و launcher در `%USERPROFILE%\.codex\local-runtimes\cherriva` و بیرون گیت نگهداری می‌شوند. `Start-Cherriva.ps1` سرویس‌های موجود را متوقف نمی‌کند و در صورت بسته‌بودن، نسخه محلی را اجرا می‌کند. مشخصات ورود اعلامی مالک فقط در دیتابیس محلی ذخیره شده‌اند؛ رمز و شماره شخصی وارد fixture/سورس/شاهد عمومی نشده‌اند. حساب محلی با push کد به لیارا منتقل نمی‌شود.

## محدودیت‌های باقی‌مانده

- ذخیره‌سازی فعلی adapter بررسی PostgreSQL و **محدود به local/test** است. metadata/رسانه در aggregate بررسی‌اند؛ نشست، OTP و محدودکننده رمز حافظه‌ای‌اند. پذیرش production، پشتیبان‌گیری/بازیابی و پیامک واقعی در گیت انتشار لازم‌اند؛ گارد موجود برداشته نشده است.
- سرچ، حساب و سبد هدر تا مراحل بعد غیرفعال‌اند؛ صفحات مقصد #28/#29 و خرید #30 اجرا نشده‌اند. این خانه خروجی بررسی محلی است، نه سایت کامل آماده انتشار عمومی.
- مدل تخفیف این برش فقط قیمت مرجع اختیاری در عرضه است؛ کوپن، کمیسیون، فرمول طلا و شارژ/مصرف واقعی کیف پول ساخته نشده‌اند.
- همه زمینه‌های #24/#25 و فیلدهای SEO/گالری/محتوای کامل، با پیاده‌سازی حداقلی خانه انجام‌شده اعلام نمی‌شوند.
- انتشار لیارا طبق دستور مالک با پارساست؛ هیچ deploy یا merge به main انجام نشده. #27 با دستور مالک بسته شد؛ والد #11 برای مراحل باقی‌مانده باز است.
