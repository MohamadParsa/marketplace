## نتیجه و مرز تحویل

PLP و جست‌وجوی هدر از همان داده پایدار بک‌آفیس تغذیه می‌شوند. هر دسته فقط محصولات منتسب به خودش را دارد؛ breadcrumb همه اجداد و دسته جاری، لینک زیرشاخه‌ها، فیلترهای صریح دسته، بازه قیمت، موجودی، مرتب‌سازی واقعی و صفحه‌بندی فراهم است. URL انتخاب‌ها را نگه می‌دارد و Refresh/Back، از جمله محل scroll، بررسی شده‌اند. کارت‌ها کنترل خرید ندارند و به URL مستقل محصول متصل‌اند؛ **ساخت PDP در #29 و خرید/حساب مشتری در #30 باقی است**.

جست‌وجوی ساده بدون موتور خارجی، نام فارسی/انگلیسی کالا و نرمال‌سازی حروف فارسی/عربی و ارقام دارد. popup قابل استفاده با کیبورد است؛ پاسخ دیررس کنار گذاشته می‌شود. دسته‌های popup با نام فارسی جست‌وجو می‌شوند. حالت loading/empty/error/retry و طرح **A — متعادل و شیک** در موبایل و دسکتاپ بررسی شدند.

هر هفت فیلد دسته در فرم موجود `/home-catalog` در دسترس است: نام فارسی/انگلیسی، توضیح، انتشار و سه متا. ویرایش مشخصات غیرمحور محصول برای تأمین داده فیلتر/کارت به همان فرم اضافه شد؛ موتور تنوع و عرضه دوباره ساخته نشد. فرم انتساب و سقف ویژگی کارت، مجوزهای عملیات را از context جاری می‌گیرد. تغییر محتوا، محصول منتشرشده‌ای را که اکنون ناموجود است مجبور به انتشار دوباره نمی‌کند.

## اجرای محلی و تحویل به پارسا

بک‌آفیس `http://localhost:8098` و storefront `http://localhost:5197` از build واقعی React و دو فرایند Go روی PostgreSQL محلی مشترک اجرا می‌شوند. تنظیم storefront: `WEB_SURFACE=storefront` و `WEB_ROOT=../storefront-web/build`؛ پنل `WEB_SURFACE=backoffice` و build خودش را دارد. buildها در گیت ثبت نمی‌شوند. مهاجرت DDL تازه لازم نبود؛ دسته SEO و محصول attributes/CreatedAt در aggregate پایدار موجود با سازگاری داده قدیمی ذخیره می‌شوند. تاریخ ساخت محصول جدید از سرور است؛ محصول قدیمی با audit ایجاد و سپس شناسه ثابت مرتب می‌شود؛ تاریخ ساختگی وارد نشده است.

داده نمونه از API مجاز روی loopback/test ساخته شده است و اطلاعات واقعی مشتری/فروشنده ندارد. حساب محلی قبلی دست‌نخورده است؛ رمز یا توکن آن وارد مخزن و تصاویر نشده است.

## محدودیت‌های روشن

جست‌وجو scan ساده Go روی snapshot repository است؛ حتی با PostgreSQL، ادعای جست‌وجوی SQL بهینه/index یا مقیاس تولید نمی‌شود. مخزن بررسی همچنان local/test است. HTML شامل متادیتای اولیه واقعی است اما محتوای شبکه React سمت مشتری رندر می‌شود؛ SSR کامل یا داده ساخت‌یافته محصول تحویل نشده است. robots محیط بررسی همچنان noindex/nofollow است. انتشار عمومی نیازمند گیت #30/#12، داده واقعی و بررسی پیکربندی تولید است.

Dockerfile/استقرار فعلی مخصوص پنل است؛ برای ارائه متای اولیه storefront، پارسا باید build سایت را با سطح وب Go بالا اجرا کند. میزبانی صرفاً استاتیک React همین HTML اختصاصی را تولید نمی‌کند. این تسک فایل استقرار را تغییر نداده و روی لیارا منتشر نکرده است.

#24 اجرای مستقل ندارد؛ هر چهار معیارش از همین تحویل شاهد دارند. #25، PDP #29 و خرید #30 همچنان بازند. breadcrumb برند در #29 طبق خواست مالک ثبت شده است: خانه ← دسته‌ها ← برند موجود ← نام محصول؛ مقصد برند ساختگی ایجاد نشود.
