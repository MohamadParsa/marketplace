# CV-LCH-01 — صفحه اصلی واقعی با چهار کروسل؛ بک‌آفیس و سایت

Issue: [#27](https://github.com/MohamadParsa/marketplace/issues/27) · والد: [#11](https://github.com/MohamadParsa/marketplace/issues/11)

## هدف بیزینسی و ترتیب

اولین خروجی قابل مشاهده، خانه‌ای با داده قابل مدیریت و پایدار باشد؛ نه نمایش fixture و نه انتظار برای کل پنل‌ها.

ترتیب تأییدشده مالک: 1 از۴. وابستگی تحویل: شروع مسیر انتشار؛ حداقل زیرساخت/کاتالوگ در همین کار؛ آماده‌سازی کارهای مستقل مراحل بعد می‌تواند موازی باشد، ولی پذیرش به همین ترتیب است. مالک/موعد انتساب نشده و تاریخ تحویل فرض نشده است.

## بک‌آفیس

1. ایجاد/ویرایش حداقل داده دسته، برند، محصول، تصویر، انتشار، تنوع و عرضه/قیمت/موجودی موردنیاز خانه؛ از مدل‌های #4/#5/#6 و زیرمجموعه لازم #24/#25 استفاده شود و کار تکراری ساخته نشود.
2. چهار جایگاه ثابت به شناسه دسته‌های موبایل، هندزفری، پاوربانک و ساعت هوشمند نگاشت شوند؛ نگاشت حداقلی typeدار در بک‌آفیس قابل اصلاح باشد. عنوان و لینک مشاهده همه با همان دسته سازگار بمانند؛ صفحه‌ساز یا افزودن سکشن دلخواه لازم نیست.
3. تصویر بنر دسکتاپ/موبایل، alt و لینک داخلی در فرم بنر موجود #7 مدیریت شود؛ نبود بنر سالم، محصولات را از دسترس خارج نکند.

## API و داده

1. ادغام سازگار شاخه‌های لازم و ذخیره پایدار کاتالوگ/رسانه؛ مخزن review محدود local/test بدون پذیرش production به‌عنوان storage عمومی منتشر نشود. migration و داده اولیه واقعی تحت کنترل دسترسی باشد.
2. API عمومی خانه فقط فیلدهای مجاز، محصول منتشرشده و دارای عرضه قابل خرید برگرداند؛ draft، اطلاعات فروشنده/مشتری و workspace خصوصی منتشر نشوند. انتخاب عرضه نماینده طبق قرارداد کاتالوگ انجام شود؛ تساوی با تأمین سریع‌تر سپس شناسه ثابت حل می‌شود؛ قیمت نقدی نهایی ثبت‌شده مبناست.
3. چهار ریل category-based ثابت، ترتیب قابل تکرار و limit محدود داشته باشند؛ شمار/مرتب‌سازی طبق قرارداد فنی انتخاب و مستند شود. کالای کم با تکرار/کالای نامرتبط پر نشود؛ صفرنتیجه fallback خالی بدون خطا باشد. Cache عمومی تنها با invalidation قیمت/موجودی/انتشار و TTL مستند.

## فرانت سایت

1. هدر، جست‌وجو، حساب/سبد، منو، بنر، دسته‌های لازم، چهار ریل به ترتیب موبایل، هندزفری، پاوربانک، ساعت هوشمند و فوتر مشترک طبق A.
2. کارت تصویر، نام، دسته و قیمت عرضه نماینده را نمایش دهد؛ افزودن به سبد و انتخاب تنوع روی کارت نیست. مشاهده همه به PLP همان دسته و کارت به PDP مستقل لینک شود.
3. تا تحویل PLP/PDP، صفحه خانه برای بررسی در staging قابل تحویل است؛ لینک‌ها و سرچ پاپ‌آپ فقط با تکمیل مراحل۲/۳ پذیرفته می‌شوند و انتشار عمومی نهایی لینک شکسته/کنترل جعلی ندارد.

## خردکردن کار برای اجرا

قرارداد/مدل و migration → mutation و فرم بک‌آفیس → API عمومی/مشتری → صفحه سایت → بررسی مجوز/خطا/هم‌زمانی مرتبط → شواهد پذیرش. هر زیربخش در همین Issue checklist دارد؛ مرز تحویل، قابلیت متصل است. تغییرات مشترک به Issue اصلی ارجاع داده شوند و دوباره اجرا نشوند.

## معیار پذیرش

- CV-LCH-01-AC01: ادمین محصول/قیمت/تصویر/موجودی را تغییر دهد؛ پس از refresh و restart داده تازه در ریل مرتبط دیده شود.
- CV-LCH-01-AC02: چهار ریل دقیقاً با دسته صحیح و ترتیب خواسته‌شده وجود داشته باشند؛ محصول draft/ناموجود در آن‌ها نمایش داده نشود و کمبود کالا تکرار مصنوعی نسازد.
- CV-LCH-01-AC03: بک‌آفیس فاقد مجوز از mutation مستقیم منع شود و API خانه داده خصوصی ندهد؛ cache پس از تغییر داده عمومی نامعتبر شود.
- CV-LCH-01-AC04: خانه در۳۹۰/۱۴۴۰ با طرح A، رنگ گیلاسی و لوگوی C به‌عنوان حرف اول نمایش داده شود؛ بنر موبایل/دسکتاپ و خطا/خالی بدون overflow باشند.
- CV-LCH-01-AC05: در تحویل خانه، قرارداد URL و شناسه مقصد کارت/مشاهده همه با API اعتبارسنجی شود؛ تکمیل صفحات مقصد و جست‌وجوی پاپ‌آپ در مراحل۲/۳ است و شاهد اتصال کامل در گیت مرحله۴ ثبت می‌شود؛ پذیرش خانه به پایان مرحله۳ وابسته نشود.

## موانع و مرز شروع

قیمت نقدی، تساوی و حداقل انتشار با پاسخ مالک برای همین برش حل شده‌اند. بخش‌های دیگر R2-Q07/R2-Q08 حل‌شده فرض نمی‌شوند. انتخاب دامنه محتوایی عمومی واقعی و storage/احراز production پیش از انتشار لازم است.

مسیرهای مرتبط موجود: CV-R2-04, CV-R2-05, CV-R2-06, CV-R2-16, CV-R2-17. این‌ها ارجاع قابلیت‌اند؛ بسته‌شدن کامل تمام Issueهای مرجع شرط خودکار این تسک نیست. زیرمجموعه استفاده‌شده باید با شاهد پذیرفته شود.

## قرارداد تحویل مشترک

طرح مرجع **A — متعادل و شیک** و لوگو طبق [راهنمای بصری جاری](../../../experiences/storefront/visual-design.md#initial-launch-brand) است؛ نشان C نقش حرف اول Cherriva را دارد. در قفل نوشتاری ترکیبی، C دوباره در کنار نشان تکرار نشود. مرجع تاریخی بدون ویرایش باقی می‌ماند. صفحه محصول مستقل است و دکمه خرید طبق طرح منتخب، نه مودال محصول یا افزودن از کارت خانه/PLP.

هر تسک شامل بک‌آفیس، API/ذخیره‌سازی و فرانت سایت است. frontend با fixture تنها تحویل محسوب نمی‌شود؛ تغییر مجاز بک‌آفیس باید در سایت دیده شود و داده با restart باقی بماند. مخفی‌کردن منو جای کنترل مجوز در سرور نیست. برای هر AC، آزمون مثبت/منفی متناسب و مرور۳۹۰/۱۴۴۰ ثبت شود؛ وضعیت اسناد in-review و اجرای این برش done است؛ مالک پس از تحویل دستور بستن Issue را داد. این وضعیت تأیید کلی همه اسناد نیست. اطلاعات خصوصی، رسید، نشانی و کیف پول cache عمومی نشوند.

در قرارداد API قبل از اجرا، DTO، validation، خطای فیلدی، unauthorized/forbidden/not-found، تعارض نسخه، pagination و retry مرتبط مشخص شوند؛ پیشنهاد نام جدول/endpoint مجوز تغییر قوانین نیست. loading، empty، error، عدم مجوز و حفظ draft پس از خطا در فرم دیده شوند. داده آزمون ساختگی و با داده عمومی واقعی جدا باشد. بستن کار فقط با شواهد اتصال انتهابه‌انتها، گزارش limitation و تطبیق طراحی مجاز است.

## تکمیل دامنه با تأکید مالک در زمان اجرا — ۲۰۲۶-۱۱-۲۱

چهار ریل دسته‌ای علاوه بر سکشن تخفیف ویژه، بنر اصلی/مکمل و میان‌بر همه دسته‌های دارای موجودی هستند. ظاهر بک‌آفیس این تحویل شامل ورود، قاب پنل و فرم‌های کاتالوگ نیز باید همان A باشد؛ استفاده از پوسته سبز قدیمی با تغییر جزئی رنگ پذیرفته نیست. ورود هر دو محیط با اصلاح نهایی مالک طبق ADR-008 است: ایمیل فقط رمز؛ موبایل انتخاب رمز یا OTP. رابط بک‌آفیس و تنظیم ایمیل/رمز در پروفایل در این برش، و رابط مشتری در #30 انجام می‌شود.

پاسخ‌های قطعی دیگر: قیمت ثبت‌شده عرضه، نقدی نهایی بدون ارسال؛ تساوی ابتدا وقفه تأمین کوتاه‌تر سپس شناسه ثابت. حداقل انتشار نام فارسی/دسته/تصویر/عرضه موجود است؛ نام انگلیسی و توضیح فعلاً اختیاری‌اند. [قرارداد دقیق و مرز اجرا](../../../architecture/contracts/homepage-launch.md)

- CV-LCH-01-AC06: تخفیف ویژه از قیمت نهایی/قبل‌تخفیف واقعی عرضه نماینده، بنرهای دو اندازه اصلی/مکمل و تمام دسته‌های دارای محصول قابل خرید از داده پنل نمایش داده شوند؛ کارت ناموجود/draft یا تخفیف غیرواقعی ساخته نشود.
- CV-LCH-01-AC07: ورود و قاب/فرم‌های پنل با A و لوگوی C تطبیق داده شوند؛ موبایل انتخاب رمز/OTP و ایمیل فقط رمز داشته باشد؛ انتخاب روش رمز پیامک نفرستد و تنظیم ایمیل/رمز همان حساب از پروفایل انجام شود.
