# CV-LCH-02 — PLP و جست‌وجوی واقعی؛ بک‌آفیس و سایت

Issue: [#28](https://github.com/MohamadParsa/marketplace/issues/28) · والد: [#11](https://github.com/MohamadParsa/marketplace/issues/11)

## هدف بیزینسی و ترتیب

مشتری بتواند از دسته و جست‌وجو به کالای درست برسد و ادمین همان فیلترها و محتوا را مدیریت کند.

ترتیب تأییدشده مالک: 2 از۴. وابستگی تحویل: CV-LCH-01؛ آماده‌سازی کارهای مستقل مراحل بعد می‌تواند موازی باشد، ولی پذیرش به همین ترتیب است. مالک/موعد انتساب نشده و تاریخ تحویل فرض نشده است.

## محل اجرای یکتا و اولویت جاری

این تسک **تنها محل اجرای تکمیل دسته/SEO و PLP/جست‌وجو** است؛ #24 مرجع کنترل نیازمندی و بدون صف/PR اجرایی جداست. اهمیت P0، ترتیب۲از۴ است؛ اجرای #28 تمام شده و شاهد هر پنج معیار در [گزارش تحویل](../issue-28-verification.md) آمده است. کار بعدی #29 است.

از #27 نام فارسی/انگلیسی، توضیح، published، آیکن/درخت و مجوز/نسخه موجود را استفاده کند؛ این‌ها دوباره ساخته نشوند. کار باقیمانده این تسک: سه فیلد SEO و فرم/ذخیره/API/HTML آن‌ها، سیاست دسته‌های درختی، فیلتر و کارت تنظیمی، فهرست و جست‌وجوی واقعی. CV-R2-16-AC01 تا04 در همین PR و با همان تست‌ها شاهد بگیرند؛ بستن قبلی #24 شرط شروع نیست.

صفحه/محتوای کامل PDP و انتخاب تنوع/فروشنده در #29 است؛ این کار فقط لینک و شناسه مقصد صحیح را تحویل می‌دهد. سبد، نشست مشتری، نشانی، ارسال و عملیات مالی در #30 است. این تحویل، PDP یا خرید را انجام‌شده اعلام نمی‌کند.

## بک‌آفیس

1. درخت دسته با نام فارسی/انگلیسی، توضیح، published، آیکن و سه فیلد SEO طبق #24؛ خصوصیات مشترک و binding صریح filter/card/axis و ترتیب طبق #5.
2. سقف عمومی ویژگی کارت و ترتیب/فهرست دسته از تنظیم typeدار حداقلی #15 مصرف شوند؛ برای تغییر این مقادیر نیاز به deploy نباشد. دامنه کامل #15 شرط نیست.
3. تنظیمات مرتب‌سازی/سنجه بازدید و فروش قبل از نمایش گزینه‌های متناظر قرارداد داشته باشند؛ گزینه پرفروش‌ترین/پربازدیدترین با ترتیب ساختگی تحویل نشود.

## API و داده

1. API فهرست عمومی با pagination، دسته هدف، فیلتر attr مجاز، موجودی، بازه قیمت و sort معتبر؛ search ساده بدون موتور خارجی؛ انتخاب اجرایی این برش scan امن Go روی snapshot پایدار repository است، نه query/index بهینه SQL.
2. سرور فقط فیلترهای دسته را بپذیرد و محصولات منتشرشده را برگرداند؛ محصول منتشرشده ناموجود مجاز با برچسب و بدون ادعای خرید است. داده draft در search/PLP نشت نکند.
3. معنی تجمیع محصولات زیرشاخه در PLP والد طبق CHQ-09 انتخاب شود؛ درخت ناوبری با انتساب خصوصیات یا ارث خودکار اشتباه نشود. metadata اختصاصی همان دسته و URL پایدار فراهم شود.

## فرانت سایت

1. breadcrumb، عنوان، زیرشاخه‌های دسته جاری و فیلترهای مربوط، موجودبودن و بازه قیمت، شبکه کارت و صفحه‌بندی؛ موبایل زیرشاخه‌ها را ببیند و دسته برگ بدون زیرشاخه فقط خودش را نشان دهد.
2. مرتب‌سازی پیش‌فرض/گران‌ترین/ارزان‌ترین/جدیدترین واقعی؛ پرفروش‌ترین/پربازدیدترین تنها پس از داده معتبر فعال شوند و در نبود داده، غیرفعال یا حذف مطابق قرارداد مصوب باشند.
3. کارت حداکثر ویژگی مجاز تنظیمی، نام/تصویر/قیمت و ناموجودی؛ کلیک به PDP مستقل. جست‌وجوی هدر با debounce، لغو/نادیده‌گرفتن پاسخ قدیمی، popup قابل استفاده با کیبورد و صفحه نتایج واقعی.
4. query/filter/sort/page در URL قابل بازگشت و refresh باشند؛ توضیح پایانی/متای PLP دسته و فوتر مشترک طبق A.

## خردکردن کار برای اجرا

قرارداد/مدل و migration → mutation و فرم بک‌آفیس → API عمومی/مشتری → صفحه سایت → بررسی مجوز/خطا/هم‌زمانی مرتبط → شواهد پذیرش. هر زیربخش در همین Issue checklist دارد؛ مرز تحویل، قابلیت متصل است. تغییرات مشترک به Issue اصلی ارجاع داده شوند و دوباره اجرا نشوند.

## معیار پذیرش

- CV-LCH-02-AC01: ادمین ویژگی فیلتر یا کارت و سقف نمایش را تغییر دهد و PLP همان تغییر را بگیرد؛ حافظه به شارژر منتسب‌نشده نرسد.
- CV-LCH-02-AC02: درخت موبایل زیرشاخه‌های معتبر و دسته برگ فقط خودش را نشان دهد؛ رفتار محصولات زیرشاخه پس از تصمیم CHQ-09 شاهد داشته باشد.
- CV-LCH-02-AC03: جست‌وجو/فیلتر/قیمت/sort/page در API و سایت یک نتیجه بدهند؛ refresh و Back انتخاب‌ها را حفظ کند و پاسخ دیررس جست‌وجو نتیجه جدید را بازنویسی نکند.
- CV-LCH-02-AC04: ناموجود منتشرشده برچسب داشته باشد، draft نشت نکند و کارت CTA خرید نداشته باشد؛ انتخاب کارت URL/شناسه صحیح PDP را بسازد؛ رندر مقصد در مرحله۳ و گیت نهایی بررسی می‌شود.
- CV-LCH-02-AC05: متای PLP هر دسته متعلق به خودش، مقدار متن امن و loading/empty/error در۳۹۰/۱۴۴۰ مطابق A باشد؛ ورودی فیلتر نامعتبر در سرور رد شود.

## موانع و مرز شروع

پرسش تجمیع CHQ-09، اثر انتشار دسته و متای خالی R2-Q08 و ترتیب پیش‌فرض با پاسخ مستقیم مالک در همین سند حل شدند. R2-Q07/R2-Q08 مربوط به محصول/robots و تغییر آینده محور باز می‌مانند و مانع این برش نیستند.

مسیرهای مرتبط موجود: CV-R2-05, CV-R2-13, CV-R2-16. این‌ها ارجاع قابلیت‌اند؛ بسته‌شدن کامل تمام Issueهای مرجع شرط خودکار این تسک نیست. زیرمجموعه استفاده‌شده باید با شاهد پذیرفته شود.

## قرارداد تحویل مشترک

طرح مرجع **A — متعادل و شیک** و لوگو طبق [راهنمای بصری جاری](../../../experiences/storefront/visual-design.md#initial-launch-brand) است؛ نشان C نقش حرف اول Cherriva را دارد. در قفل نوشتاری ترکیبی، C دوباره در کنار نشان تکرار نشود. مرجع تاریخی بدون ویرایش باقی می‌ماند. صفحه محصول مستقل است و دکمه خرید طبق طرح منتخب، نه مودال محصول یا افزودن از کارت خانه/PLP.

هر تسک شامل بک‌آفیس، API/ذخیره‌سازی و فرانت سایت است. frontend با fixture تنها تحویل محسوب نمی‌شود؛ تغییر مجاز بک‌آفیس باید در سایت دیده شود و داده با restart باقی بماند. مخفی‌کردن منو جای کنترل مجوز در سرور نیست. برای هر AC، آزمون مثبت/منفی متناسب و مرور۳۹۰/۱۴۴۰ ثبت شود؛ وضعیت اسناد in-review و اجرای این تسک done است؛ merge و استقرار عمومی انجام نشده است. اطلاعات خصوصی، رسید، نشانی و کیف پول cache عمومی نشوند.

در قرارداد API قبل از اجرا، DTO، validation، خطای فیلدی، unauthorized/forbidden/not-found، تعارض نسخه، pagination و retry مرتبط مشخص شوند؛ پیشنهاد نام جدول/endpoint مجوز تغییر قوانین نیست. loading، empty، error، عدم مجوز و حفظ draft پس از خطا در فرم دیده شوند. داده آزمون ساختگی و با داده عمومی واقعی جدا باشد. بستن کار فقط با شواهد اتصال انتهابه‌انتها، گزارش limitation و تطبیق طراحی مجاز است.

## تصمیم‌های مالک هنگام اجرای #28 — ۲۰۲۶-۱۱-۲۱

PLP فقط محصولات منتسب به همان دسته را دارد؛ محصولات زیرشاخه تجمیع نمی‌شوند و زیرشاخه‌ها لینک ناوبری دارند. خاموش‌کردن انتشار/بایگانی مادر، نمایش عمومی کل شاخه را می‌بندد و published ذخیره‌شده فرزندها را تغییر نمی‌دهد. پیش‌فرض فهرست موجودها اول، سپس جدیدترین واقعی و شناسه ثابت است؛ پرفروش‌ترین/پربازدیدترین تا داشتن سنجه واقعی نمایش داده نمی‌شوند. متای خالی: عنوان از نام دسته و Cherriva، توضیح از متن همان دسته و keywords خالی؛ ارث از مادر ندارد. Breadcrumb خانه و همه دسته‌های والد قابل نمایش تا دسته جاری در PLP الزامی است. این پاسخ‌ها CHQ-09 را فقط برای تجمیع PLP و R2-Q08 را فقط برای همین انتشار/متای دسته حل می‌کنند.
