## قرارداد فنی اتصال

- سرویس‌ها از `catalog.ProductInteractions` استفاده کنند. آمادگی هر سرویس مستقل و فقط پس از اجرای واقعی آن روشن شود؛ عمومی‌بودن مؤثر محصول/شاخه نیز کنترل شود.
- `NewSubmissions` فقط گیت قابلیت است؛ در handler احراز هویت، مجوز، validation و سیاست تأیید مستقل اعمال شوند. `ApprovedContentVisible` مجوز نمایش داده تأییدنشده نیست؛ query باید وضعیت تأیید را فیلتر کند. `TeamReplies` نیز مجوز کاربر عادی ایجاد نمی‌کند.
- خاموشی تنظیم، داده را حذف نکند و مجوز پاسخ تیم را گسترش ندهد. سناریوهای رد دسترسی، مشاهده draft، تغییر هم‌زمان تنظیم و ارسال، و حفظ متن در خطای فرم لازم‌اند.
- پیش از این اتصال، تصمیم‌های باز CHQ-10 درباره مجازبودن ثبت/سیاست تأیید و موارد وابسته حل شوند؛ پاسخ آن‌ها از R2-Q09 برداشت نمی‌شود.

## وضعیت شواهد

آزمون HTTP ذخیره تنظیمات و تست دامنه قواعد در #25 پاس شده‌اند. آزمون انتها‌به‌انتهای API ثبت، moderation و نمایش داده واقعی هنوز اجرا نشده، چون سرویس‌ها ساخته نشده‌اند. گیت عمومی #11/#12 جداگانه باز است؛ این راهنما اجازه merge یا استقرار نیست.
