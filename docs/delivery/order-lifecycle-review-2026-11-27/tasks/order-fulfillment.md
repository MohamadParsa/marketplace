# CV-ORDER-REV-06 — عملیات سفارش واقعی

Issue: [#136](https://github.com/MohamadParsa/marketplace/issues/136) · مسئول @eliassarband · اجرای ترتیبی با دستور صریح مالک در ادامه همین گفتگو انتخاب شد؛ بستن پس از تست، مدارک و push.

## مسئله و مسیر

پس از پرداخت موفق، ادمین یا عضو مجاز فروشگاه، شروع پردازش را ثبت کند؛ سپس تأمین‌نشده → تأمین‌شده → در حال آماده‌سازی → ارسال → تحویل با تاریخچه و نمایش مستقل پیش برود. [قواعد مشترک](../../../domains/orders/lifecycle-review-2026-11-27.md) مرجع است. سفارش‌های checkout از مسیر legacy که آن‌ها را رد می‌کند عبور داده نشوند؛ API واقعی و فرم متناظر بک‌آفیس/سلر لازم است.

## دامنه و تعامل

مجوز transition سمت سرور و store-scoped، کنترل همه اقلام گروه، توقف عدم تأمین و تخصیص جایگزین موجود حفظ شوند. نام و نشانی مشتری فقط با شرایط تأیید تأمین قواعد موجود آزاد شوند. روش حمل نوع شناسه لازم برای ارسال را تعیین کند؛ این نوع در snapshot مرسوله بماند. پست: کد رهگیری؛ پیک: کد تحویل طبق سیاست پاسخ‌داده‌شده Q07. چندبسته‌ای/چندکد طبق R17 ارسال ناقص مجاز نمی‌کند.

ارسال یعنی تحویل به حمل‌کننده، نه صرف صدور کد. تحویل مشتری رویداد جداست؛ اختیار مشتری/پشتیبانی با دلیل طبق R18/R20 حفظ و گذشت زمان جای شاهد دریافت ننشیند. تکمیل سفارش و تجمیع خرید والد طبق REV-03/Q03 باشد. اصلاح کد/مرحله بدون حذف تاریخچه و فقط در حدود Q10.

## پذیرش و آزمون لازم

- FEAT-BO-ORDER-REV-006-AC01: پرداخت ناموفق/نامشخص شروع پردازش را ببندد؛ پس از پرداخت موفق، اقدام صریح ادمین/فروشگاه مجاز ثبت شود و هر مرحله با عامل/زمان/نسخه دیده شود.
- FEAT-BO-ORDER-REV-006-AC02: فروشگاه دیگر با API مستقیم نتواند بخواند یا تغییر دهد؛ تأیید بعضی اقلام اطلاعات مشتری را زودتر باز نکند. on-hold و تأمین جایگزین کنترل شوند.
- FEAT-BO-ORDER-REV-006-AC03: ارسال پست بدون tracking و پیک بدون delivery-code لازم رد شود؛ نام روش معیار hard-code نباشد. تغییر تنظیم جاری شرط سفارش قدیمی را عوض نکند.
- FEAT-BO-ORDER-REV-006-AC04: دو اقدام هم‌زمان ارسال/لغو یا تکرار ارسال، وضعیت و ظرفیت را ناسازگار نکنند؛ ظرفیت بعد از ارسال آزاد نشود. ثبت همه بسته‌های گروه شرط ارسال کامل باشد.
- FEAT-BO-ORDER-REV-006-AC05: تحویل یک مرسوله از خرید چندفروشنده‌ای، سایر مرسوله‌ها را تحویل/تکمیل نکند؛ دریافت معتبر طبق سیاست تکمیل کند. ثبت صرف کد، تحویل محسوب نشود.
- FEAT-BO-ORDER-REV-006-AC06: Go/API/PG، restart و مرورگر برای ادمین/دو فروشگاه/مشتری با داده ساختگی و شاخه‌های خطا/عدم‌مجوز ثبت شوند؛ رگرسیون #10/#16/#123 پوشش داده شود.
