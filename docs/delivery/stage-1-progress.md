## نسخه قابل بررسی صفحات

رابط فارسی RTL با React Router، TanStack Query، MUI و فرم ورود React Hook Form/Zod ساخته شده است. صفحات داده را از API Go دریافت می‌کنند؛ mutationها در backend اجرا، مجوزسنجی و audit می‌شوند. داده ساختگی در adapter حافظه و قابل بازنشانی با restart است؛ این نسخه محصول عملیاتی کامل نیست.

## شواهد اجرا

- `apps/api/internal/application/backoffice/service_test.go`: مجوز، پوشیده‌سازی مالی، idempotency در retry هم‌زمان، تعارض نسخه، محافظ آخرین مدیر، عدم ثبت مالی unknown و آزادسازی رزرو شکست قطعی.
- `apps/api/internal/bootstrap/backoffice_test.go`: ورود/نشست و درخواست مستقیم API، عدم افشای کاربران/مالی به viewer، ابطال دسترسی حساب غیرفعال.
- `tests/e2e/backoffice-smoke.py`: ورود، پیمایش ۱۵ نما، ساخت فروشگاه، تعیین نتیجه مالی، audit، جزئیات سفارش، layout موبایل و خروج؛ بدون خطای runtime مرورگر.
- `go test -race ./...`، `go vet ./...` و build/typecheck رابط اجرا می‌شوند؛ اجرای کل BDD محصول ادعا نشده است.

## استقرار

بسته [استقرار Liara](../../deploy/liara/README.md) با Docker چندمرحله‌ای آماده است. API و خروجی مستقل frontend از یک origin ارائه می‌شوند. ساخت container محلی به‌علت اجرا نبودن Docker daemon آزموده نشده بود؛ build چندمرحله‌ای container اکنون روی Liara با موفقیت انجام شده است.

وضعیت فعلی: **نسخه بررسی روی Liara منتشر و آزموده شد**.

- برنامه: `marketplace-bo-review`، پلتفرم Docker، یک نمونه روی `small-g2` با feature plan `basic`.
- شبکه: `marketplace-review` در حساب شخصی کاربر.
- نشانی: [بک‌آفیس نسخه بررسی](https://marketplace-bo-review.liara.run).
- release ساخته‌شده: `aaknbxkd912k`؛ build، push و health check پلتفرم موفق بودند.
- بررسی HTTPS: صفحه اصلی پاسخ ۲۰۰، `/health/ready` وضعیت ready و درخواست بدون نشست به workspace پاسخ ۴۰۱ داشت.
- smoke test روی نشانی عمومی: ورود آزمون، پیمایش ۱۵ نما، ایجاد فروشگاه ساختگی، نتیجه مالی شبیه‌سازی‌شده، audit و خروج با موفقیت و بدون خطای runtime مرورگر انجام شدند.
- طبق خروجی Liara، زیردامنه پیش‌فرض فقط یک هفته پس از اولین deployment معتبر است؛ دامنه اختصاصی هنوز ثبت نشده است.

این انتشار، نسخه بررسی با داده حافظه‌ای/ساختگی است و تکمیل گیت کامل مرحله ۱ یا آماده‌بودن محصول برای داده واقعی را اعلام نمی‌کند.

## وابستگی‌های تأیید و قواعد

پاسخ‌های کاربر در [دفتر پرسش‌ها](../product/open-questions.md) معتبرند، اما پاسخ‌های تجمیعی قبلی همه جزئیات هر Q را نبسته‌اند. وضعیت حل‌شده نباید به تأیید فرضی همه schemaها یا گیت `done` تعبیر شود. برای مثال HTML allowlist دقیق، فرمول تعدیل مالی و همه سیاست‌های ساعت/بازیابی هنوز نیازمند مشخصات اجرایی‌اند. انتخاب provider واقعی مانع مرور نسخه آزمون نیست.

قرارداد مسیرهای فعلی: [API-BO-REVIEW-001](../architecture/contracts/backoffice-review.md). وضعیت تأیید اسناد مستقل از پیشرفت اجرا باقی می‌ماند.

[طرح ۰.۲ بک‌آفیس و پنل فروشنده](../experiences/backoffice/panel-design.md) در بسته مستقل بازبینی، ۲۷ صفحه و ورود را پوشش می‌دهد. شناسه صفحه در آن بسته با شناسه جدول نسخه بررسی بالا مستقل است. برای نمونه، فروشگاه‌ها در بسته BO-04 و در این گزارش BO-03 است.
