# CV-SF-UX-01 — افزودن مرتب‌سازی پرفروش‌ترین با سنجه واقعی فروش

## مسئله و نتیجه

کاربر بتواند در PLP و نتایج جست‌وجو، کالاها را بر اساس فروش واقعی مرتب کند؛ شمار بازدید، موجودی یا داده ساختگی جای فروش ننشیند.

## دامنه و وضعیت

سایت مشتری برای مهمان/مشتری، API سنجه و بخش محدود تنظیم مجاز بازه در بک‌آفیس. **فقط برنامه‌ریزی؛ شروع اجرا پس از انتخاب صریح مالک**. اولویت P2 پیشنهادی است و ترتیب ثبت، صف اجرای اجباری نیست. طرح A، primary فعلی و لوگوی C چریوا مرجع‌اند. قواعد خصوصی/مجوزهای جاری حفظ شوند. [صف و مرز مشترک](../ux-followups.md).

## خواسته قطعی مالک

- گزینه «پرفروش‌ترین» به sort اضافه شود؛ پیش‌فرض فعلی موجودها اول/جدیدترین عوض نشود.
- قاعده موجود DOM-CATALOG-001-R20 مرجع است: تعداد خالص واحدهای فروخته‌شده محصول در بازه قابل تنظیم با پیش‌فرض۳۰روز؛ جمع تنوع‌ها و فروشنده‌ها با کسر لغو/استرداد. شارژ کیف پول، اعلام واریزِ بررسی‌نشده و رزرو، فروش قطعی نیستند.

## طراحی اجرایی پیشنهادی

- پیشنهاد: توکن best-selling در قرارداد sort و URL، projection مشتق‌شده از رویدادهای معتبر خرید و تنظیم مجاز بازه در بک‌آفیس؛ بدون ثبت فروش فرضی در داده واقعی.
- SFUX-Q01: مرز زمانی ورود قلم به بازه، زمان/دقت به‌روزرسانی سنجه و تساوی باید پیش از پیاده‌سازی سنجه قطعی شوند؛ پیشنهاد موجود حوزه، زمان پرداخت قطعی است. ناموجودها طبق قرارداد جاری انتهای فهرست بمانند.
- نسخه/انقضای کش لیست با تغییر فروش، لغو/refund و گذر مرز بازه سازگار شود؛ فقط کلید sort تازه برای پاسخ ثابت کافی نیست.

## حالت‌های جایگزین و کنترل صحت

داده خالی/کم‌تعداد، خطا و retry، شبکه کند، انتخاب قبلی، Refresh/Back و نمایش موبایل بررسی شوند؛ جزئیات مرتبط در پذیرش زیر آمده‌اند. داده آزمون ساختگی/ایزوله باشد و حساب، سفارش یا مالی واقعی برای نمایش تغییر نکند. در کار نمایشی، مجوز یا mutation تازه‌ای ایجاد نشود؛ در کار دارای API همان کنترل مالکیت و مجوز فعلی برقرار بماند.

## پذیرش

- CV-SF-UX-01-AC01: با انتخاب پرفروش‌ترین، URL و API گزینه معتبر یکسان داشته باشند و Refresh/Back انتخاب را حفظ کنند؛ گزینه‌های قبلی و پیش‌فرض عوض نشوند.
- CV-SF-UX-01-AC02: در داده ایزوله، فروش۳و۴واحد از دو تنوع/سلر یک محصول با۲واحد لغو/refund مرتبط، سنجه خالص۵ بدهد؛ یک قلم دوبار کسر و ارسال مجدد دوبار فروش شمرده نشود.
- CV-SF-UX-01-AC03: بازه۳۰روز و تنظیم مجاز آن، نبود سابقه، تساوی و مرز زمانی پس از رفع SFUX-Q01 پوشش داده شوند؛ داده مالی واقعی تغییر نکند.
- CV-SF-UX-01-AC04: پرداخت/لغو/refund جدید و تغییر بازه، پاسخ کش‌شده قدیمی را طبق سیاست سنجه اصلاح کند؛ پنل و API دسترسی تنظیم را کنترل کنند.
