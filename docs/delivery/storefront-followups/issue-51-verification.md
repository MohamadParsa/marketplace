# نتیجه #51

BusyRegion، BusyOverlay و LoadingPlaceholder، progress نامعین گیلاسی، aria-busy و اعلان خارج جریان صفحه دارند. ناحیه درگیر با inert از تعامل تکراری و Tab محافظت می‌شود؛ محتوای قبلی با همان ارتفاع می‌ماند و focus پس از نتیجه، در صورت باقی‌ماندن کاربر در همان ناحیه، بازمی‌گردد. reduced-motion انیمیشن را متوقف می‌کند. درصد ساختگی وجود ندارد.

## پوشش

| ناحیه | رفتار |
| --- | --- |
| PDP | دریافت اولیه، تغییر تنوع/فروشنده و selection؛ متن درحال‌به‌روزرسانی از layout حذف، AbortController مانع نتیجه انتخاب قبلی |
| کنترل خرید و سبد | افزودن، popup حاصل، افزایش/کاهش/حذف و تعویض تنوع/فروشنده؛ کنترل خرید همان اندازه و برچسب قبلی را دارد |
| آدرس | دریافت/ثبت/حذف؛ فرم modal نیز overlay و محافظ بستن حین ثبت دارد؛ استان/شهر از config محلی و همگام خوانده می‌شوند، درخواست شبکه مستقل ندارند |
| wizard | دریافت prepare، preview پس از آدرس/روش/اسلات، رزرو quote و ثبت سفارش؛ خطا loading را برداشته و انتخاب معتبر را نگه می‌دارد |
| سفارش/کیف پول | بازخوانی صریح، اقدام تأیید/لغو، اعلام واریز، رسید، درخواست بازپرداخت و شارژ؛ polling پس‌زمینه سفارش عمداً صفحه را هر۱۵ثانیه مسدود نمی‌کند |
| حساب/ورود | OTP/رمز/بازیابی و ذخیره پروفایل با همان useAction |
| خانه/PLP/search/menu | placeholder اولیه، overlay روی نتایج موجود و فیلترهای موبایل، popup جست‌وجو و دریافت دسته‌ها |

پیاده‌سازی مربوط به routeهای فعال main است؛ نمونه‌های قدیمی product-modal و checkout/demo وارد فلو فعال نشده‌اند. popup بعد افزودن فقط پس از نتیجه موفق باز می‌شود؛ تعویض عرضه در popup سبد نیز همان جزء را مصرف می‌کند. انتخاب همگام نشانی/ارسال/اسلات بدون شبکه، بارگذاری ساختگی ندارد؛ preview/quote وابسته به آن‌ها پوشش دارند. overlay داده خصوصی در Redis یا کش عمومی ذخیره نمی‌شود.

## کنترل ارسال دوباره

useAction قفل هم‌زمان و کلید idempotency قبلی را حفظ می‌کند. mutate سبد اکنون در provider قفل مشترک دارد: درخواست تکراری درحال‌اجرا همان Promise را می‌گیرد؛ عملیات متفاوت تا پایان رد می‌شود. کلید بر اساس حساب+ورودی+نسخه تا پاسخ موفق نگه داشته می‌شود و شکست مبهم شبکه کلید تازه نمی‌سازد. این محافظ در طول عمر همان صفحه/provider است؛ حفاظت پایدار مالی/نسخه سبد همچنان سمت سرور است. هیچ auto-retry مالی اضافه نشد.

## بررسی

[۲۲کنترل مرورگر](../../../tests/e2e/stable-progress.cjs) موفق: ثبات مختصات دکمه در تأخیر تنوع، inert، نتیجه آخر، progress بدون درصد، خطای مبهم سبد و کلید یکسان تلاش دوباره، افزایش/کاهش/حذف، دو مرحله wizard، خطای preview و retry، ثبت فقط یک‌بار، حفظ quote/رضایت، cascade آدرس و جلوگیری از بستن modal، خطای واریز و حفظ مبلغ، موبایل۳۹۰ و reduced-motion، بدون runtime pageerror. build/typecheck و lint نیز موفق‌اند.

[۸کنترل عمومی تکمیلی](../../../tests/e2e/public-progress.cjs) نیز موفق: ثبات گرید PLP حین sort، حذف متن درون‌جریان، خطا/تلاش دوباره با حفظ sort، overlay جست‌وجو و فیلتر موبایل؛ خطای503 عمدی و بدون runtime pageerror. در مجموع۳۰کنترل برای #51.

تمام mutationهای این سناریو در شبکه مرورگر fixture و پاسخ‌های کنترل‌شده‌اند؛ هیچ سفارش، کاربر، واریز، نشانی یا داده مالی در دیتابیس ثبت نشد. یک قطع ارتباط سبد و دو409 عمدی برای پذیرش خطا استفاده شدند؛ موفقیت این تست تأیید درگاه یا پرداخت واقعی نیست. منطق مالی، شماره سفارش و مجوزها تغییر نکردند.
