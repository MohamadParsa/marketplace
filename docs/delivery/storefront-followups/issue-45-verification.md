# نتیجه #45

گزینه `best-selling` در PLP/جست‌وجو و API اضافه شد؛ انتخاب در URL، Refresh و Back حفظ می‌شود. پیش‌فرض قبلی و طرح A برقرارند؛ ظاهر radio/چیپ عمداً در تسک #50 مانده است. [شرح و ACها](tasks/cv-sf-ux-01-best-selling-sort.md).

SFUX-Q01 با پاسخ مستقیم مالک حل شد: زمان پرداخت قطعی سفارش، بازه لغزان۳۰روز، موجودها اول، تساوی جدیدترین سپس شناسه ثابت و تازگی حداکثر۶۰ثانیه. بازه از تنظیمات نمایش کالا در کتابخانه خصوصیات بک‌آفیس، با مجوز مستقل `settings.sales-window`، version/audit/idempotency قابل تغییر است. دامنه۱تا۳۶۵۰روز حد فنی است؛ مقدار قدیمی/غایب۳۰خوانده می‌شود و برای این default نیازی به تغییر داده قبلی نیست.

## محاسبه و محدودیت‌ها

- مبنا `Purchase.ConfirmedAt` همراه سفارش فروشگاهی پرداخت‌شده همان checkout است؛ این زمان پس از debit سفارش از کیف پول و تأیید خرید ثبت می‌شود. شارژ، واریز تأییدشده بدون مصرف سفارش، رزرو و درخواست لغو هنوزتأییدنشده، فروش نیستند.
- تعداد اقلام تمام تنوع‌ها و فروشنده‌های همان محصول جمع می‌شود. لغو خرید/سفارش/قلم و استرداد قطعی همان قلم از آن حذف می‌شوند؛ refund-pending فروش را پیشاپیش کم نمی‌کند. انتقال refund موفق مرتبط با همان order/item حتی با رکورد تکراری، تنها یک بار قلم را حذف می‌کند؛ ارسال مجدد یا واگذاری به فروشنده دیگر فروش تازه‌ای اضافه نمی‌کند.
- بازه `(now - days×24h, now]` است؛ آینده و مرز دقیق پایین داخل بازه نیستند. محصول بدون سابقه صفر است. پیش از سنجه، موجودبودن بررسی می‌شود و سپس فروش نزولی، جدیدترین و ID ثابت.
- مدل فعلی استرداد قلمی **تمام تعداد همان قلم** را پشتیبانی می‌کند؛ استرداد وجه عمومی کیف پول مرجع تعداد محصول نیست و از مبلغ پول، تعداد حدس زده نمی‌شود. استرداد جزئیِ تعداد درون یک قلم، هنوز مدل/فلو مستقلی ندارد و در این تسک اضافه نشده است. سناریوی۷منهای۲با قلم۲واحدیِ مستردشده پوشش داده شد.
- سابقه فروش SQL Server مبدأ وارد نشده؛ رتبه فقط از خریدهای ثبت‌شده چریوا ساخته می‌شود. در داده واردشده فاقد سابقه خرید، تساوی واقعی است؛ برای نمایش، فروش ساختگی در دیتابیس اصلی محلی ثبت نشد.

## ذخیره و کش

migration۸ جدول مشتق‌شده `catalog_sales_state` را اضافه می‌کند؛ payload فقط product_id، تعداد خالص قلم و paid_at و بازه تنظیم‌شده دارد، نه user/order/payment ID، نشانی یا اطلاعات بانکی. این ورودی داخلی در PostgreSQL است؛ در پاسخ عمومی یا Redis قرار نمی‌گیرد. startup آن را بازسازی می‌کند و هر writer در تراکنش aggregate، revision مستقلش را فقط با تغییر ورودی واقعی فروش عوض می‌کند. جدول‌های مالی/هویتی بازنویسی نمی‌شوند.

برای best-selling، revision فروش و bucket دقیقه در args کلید listing قرار دارند؛ TTL لیست حداکثر۶۰ثانیه است و گذر زمان بدون هیچ write هم رتبه را تازه می‌کند. بقیه sortها همین query اضافی فروش را ندارند. تغییر سنجه به‌تنهایی نسخه PDPهای نامرتبط را عوض نمی‌کند. schema کش عمومی v4 شد تا sort_options قدیمی مصرف نشود؛ warmup startup و fallback برقرارند.
