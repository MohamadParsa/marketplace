# آمادگی برای پیاده‌سازی

این فهرست برای هر قابلیت یا برش مستقل بررسی می‌شود، نه لزوماً کل محصول.

- [ ] مسئله، دامنه داخل و خارج، نقش و نتیجه مورد انتظار مشخص است.
- [ ] سند قابلیت و اسناد حوزه، قرارداد و کیفیت مؤثر بر آن تأییدشده‌اند؛ موارد نامرتبط با دلیل مشخص‌اند.
- [ ] مالک و تأییدکننده مشخص‌اند؛ اطلاعات فراداده کامل است.
- [ ] اصطلاحات و مالکیت داده، مجوزها و مرز داده هر فروشنده روشن‌اند.
- [ ] پیش‌شرط، مسیر اصلی و مسیرهای خطا و تغییر وضعیت لازم روشن‌اند.
- [ ] ورودی، اعتبارسنجی، خروجی و قرارداد مورد نیاز تعیین شده‌اند.
- [ ] سناریوهای پذیرش با نتیجه قابل مشاهده نوشته شده‌اند.
- [ ] وابستگی به محیط‌های دیگر و سرویس‌های بیرونی تعیین شده است.
- [ ] پرسش مسدودکننده و تعارض حل‌نشده وجود ندارد.
- [ ] قابلیت در جدول ردیابی و برش تحویل لینک شده است.

ظاهر صفحات می‌تواند به طراحی جداگانه لینک شود؛ اگر طراحی برای اجرای قابلیت لازم است، آن هم باید پیش از شروع همان بخش روشن باشد. تصمیم‌های فنی لازم فقط به اندازه همین برش باید گرفته شوند.

## اولویت پنل‌ها و اعتبار بررسی

دامنه مرحله اول طبق برنامه تحویل شامل تمام بخش‌های بک‌آفیس و پنل فروشنده با بررسی داده آزمایشی است؛ هر قابلیت بر اساس همین مرحله ارزیابی شود. بررسی پنل با داده آزمون از موفقیت خرید/درگاه واقعی جدا گزارش شود؛ آماده‌بودن فرم کاتالوگ به معنی آماده‌بودن چرخه مالی نیست. نبود سایت مشتری نباید مجوز ساخت مسیر سفارش دستی یا ورودی مالی بدون نیازمندی مصوب تلقی شود.

## گزارش آمادگی

برای هر برش، نتیجه بررسی، تاریخ، بررسی‌کننده، موارد نامرتبط و دلیل آن‌ها، موانع و لینک تصمیم‌ها را کنار ردیف برش ثبت کنید. هیچ علامت این فایل به‌طور کلی به معنی آماده‌بودن همه قابلیت‌ها نیست.
