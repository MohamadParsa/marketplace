# CV-R2-01 — هویت واحد، نقش admin و عضویت چندبه‌چند

Issue: [#1](https://github.com/MohamadParsa/marketplace/issues/1) · پاسخ‌های مالک: [R2-Q01](https://github.com/MohamadParsa/marketplace/blob/main/docs/product/open-questions.md#پرسشهای-اصلاحات-جاری)، [R2-Q02](https://github.com/MohamadParsa/marketplace/blob/main/docs/product/open-questions.md#پرسشهای-اصلاحات-جاری) · [ADR-005](../../../decisions/adr-005-review-v1-1-product-responses.md)

این مشخصات بازنویسی پس از #13 و در وضعیت in-review است. اجرای CV-R2-01 در دامنه داده آزمون کامل است؛ تأیید سند، گیت کل پنل‌ها و اتصال واقعی جدا هستند.

## هدف بیزینسی و نتیجه

خریدار، کاربر پنل و عضو فروشگاه با یک User کار کنند؛ admin اختیار تعیین نقش و adminهای دیگر را داشته باشد.

## داخل دامنه

- User مرجع یکتا؛ نقش‌ها و عضویت‌ها رابطه مستقل با همان شناسه‌اند؛ چند کاربر/فروشگاه و چند فروشگاه/کاربر پشتیبانی شوند.
- دسترسی مؤثر union جفت‌های مجوز و scope است؛ مجوز موجودی در A با مجوز مشاهده B ترکیب نشده و ویرایش B ایجاد نکند.
- نقش admin اختیار مدیریت نقش و adminهای دیگر دارد؛ مشتری یا فروشنده با دست‌کاری درخواست حق افزایش اختیار نگیرد.

## راه‌حل و داده پیشنهادی

داده منطقی User، RoleGrant(user,role,scope) و StoreMembership؛ کنترل server-side در query، mutation و خروجی. خطاهای عدم مجوز و تعارض نسخه اطلاعات خصوصی ندهند.

## دسترسی، خطا و حالات

مجوز هر query و عملیات در سرور و همراه scope انتساب کنترل شود؛ خطای اعتبارسنجی کنار فیلد، loading/empty/error/forbidden و conflict متناسب با عملیات دیده شوند. draft معتبر از بین نرود و retry اثر تکراری ایجاد نکند. برای کار معوق این‌ها معیار فاز فعال‌شده‌اند؛ وجود فرم نمونه شاهد اجرا نیست.

## بخش مسدود، خارج محدوده یا شرط شروع

[R2-Q02](../../../decisions/adr-005-review-v1-1-product-responses.md#r2-q02) سیاست ادمین را تعیین کرده است. بخش‌های مورد نیاز این کار از CV-IAM-03 و CV-FND-04 (رجیستری، مدیریت نقش و schema هویت آزمون) بررسی شده‌اند؛ این تحویل پذیرش سایر دامنه‌ها و schema عملیاتی آن تسک‌ها نیست.

اصل پنل/سلر کامل با داده آزمون پیش از سایت حفظ شود. مخزن/پروژه، provider، مقررات و تصمیم باز از fixture یا رابط استنباط نشود؛ اتصال واقعی گیت مستقل دارد.

## معیار پذیرش

- CV-R2-01-AC01: خرید/پروفایل/پنل/دو عضویت فروشگاه به یک User وصل شوند و تغییر نما حساب تازه نسازد.
- CV-R2-01-AC02: کاربر مجاز موجودی A و فقط مشاهده B بتواند A را ویرایش کند و درخواست مستقیم ویرایش B رد شود.
- CV-R2-01-AC03: admin نقش و admin دیگر تعیین کند؛ کاربر فاقد مجوز همان API رد شود و تغییر اختیار قابل ردیابی باشد.

## شاهد پایان پیاده‌سازی

گزارش integration/API با حداقل دو فروشگاه و یک کاربر چندنقشی؛ درخواست مثبت/منفی و سابقه تغییر نقش. تصویر منوی مخفی‌شده به‌تنهایی کافی نیست.

گزارش تحویل: شناسه کار، فایل/قرارداد، رفتار قبل/بعد، داده آزمون و نتیجه هر AC، مجوز/scope، موارد باز و لینک شاهد. mock، integration/API، browser و provider مستقل گزارش شوند.
