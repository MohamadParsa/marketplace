# CV-R2-16 — تکمیل محتوای دسته، انتشار و سئوی PLP

Issue: [#24](https://github.com/MohamadParsa/marketplace/issues/24)

## مسئله و نتیجه

مدل کوچک دسته فقط نام واحد/آیکن/درخت/خصوصیات و Archived دارد. طبق درخواست مالک۲۰۲۶-۱۱-۲۱، محتوای دوزبانه و انتشار و SEO دسته لازم است. #4/#5 این دامنه را کامل نکرده‌اند؛ این کار تکمیلی است و آن Issueها بازگشایی نمی‌شوند.

## منابع و وابستگی

مرجع فیلدها و تفکیک نیاز قطعی از پیشنهاد: [DOM-CATALOG-CONTENT-001](../../../domains/catalog/content-and-seo.md). وابستگی: [CV-R2-04](cv-r2-04-category-brand-media.md) و [CV-R2-05](cv-r2-05-shared-attributes.md) برای سازگاری مدل فعلی، و CV-CAT-01 پایه. تکمیل پنل W1 مقدم بر مصرف سایت #11 در W3 است؛ اولویت/موج پیشنهادی‌اند و مسئول/موعد تخصیص نشده‌اند.

## دامنه و ورودی

فرم دسته درختی موجود به گروه‌های «نام و محتوا»، «انتشار» و «SEO» تقسیم شود: نام فارسی، نام انگلیسی، توضیحات، published، meta title، meta keywords، meta description. همان شناسه، والد، آیکن، انتساب خصوصیات و نسخه حفظ شوند. داشتن فیلد قطعی است؛ الزام پرکردن، default و محدودیت طول در R2-Q07/R2-Q08 تعیین می‌شوند.

## گام‌های قابل اجرا و راه‌حل پیشنهادی

1. قرارداد typed و validation را برای فیلدهای بالا و سازگاری Name فعلی تدوین؛ ابهام انتشار دسته را از R2-Q08 حل کند.
2. مدل/ذخیره‌سازی آزمون/DTO و mutation مجاز با version و audit تکمیل شود؛ Archived برای انتشار بازاستفاده نشود.
3. فرم مشترک ایجاد/ویرایش، خواندن مجدد و خطاها اضافه؛ آیکن و خصوصیات قبلی regression نکنند.
4. DTO عمومی اختصاصی PLP برای داده قابل انتشار و سئو آماده شود؛ اتصال نهایی HTML/SEO سایت در #11 با شاهد جدا انجام شود.
5. شواهد ACها و ردیابی ثبت شوند؛ migration/مقادیر fixture قدیمی در صورت لزوم صریح مستند شوند، نه فرض داده واقعی قدیمی.

## معیار پذیرش

- CV-R2-16-AC01: مدیر مجاز تمام هفت فیلد دسته را ثبت کند و پس از بارگذاری دوباره مقادیر بدون از بین‌رفتن والد/آیکن/خصوصیات دیده شوند.
- CV-R2-16-AC02: انتشار و بایگانی یک فیلد نباشند؛ مطابق سیاست منتخب R2-Q08، پیش‌نویس در داده عمومی نشت نکند و تغییر وضعیت رفتار فرزندان را به‌طور مستند رعایت کند.
- CV-R2-16-AC03: داده عمومی و متادیتای دسته الف به همان PLP وصل شود و با دسته ب یا تنظیم عمومی جایگزین نشود؛ پذیرش HTML واقعی در #11 گزارش مستقل داشته باشد.
- CV-R2-16-AC04: API فاقد مجوز، ورودی نامعتبر و نسخه قدیمی را بدون تغییر قبلی رد کند؛ ذخیره محتوای دسته قیمت/موجودی محصولات را تغییر ندهد.

## بخش مسدود و خارج دامنه

R2-Q07 اعتبارسنجی/متن و R2-Q08 انتشار/SEO فقط مسیر وابسته را متوقف می‌کنند؛ طراحی فرم و قرارداد draft مستقل قابل پیشروی‌اند. noindex/nofollow دسته در این درخواست نیامده و از محصول تعمیم داده نمی‌شود. CMS، زیرسایت‌ها و تغییر قواعد کمیسیون خارج دامنه‌اند.

## دسترسی، خطا و شاهد پایان

loading/empty/error و خطای کنار فیلد دیده شوند؛ شکست ذخیره draft فرم را از بین نبرد. درخواست مستقیم فاقد مجوز در سرور رد شود. ویرایش هم‌زمان با version بررسی و conflict بدون بازنویسی داده معتبر برگردد؛ سابقه تغییر شامل عامل/مرجع/نسخه باشد. آزمون API موفق/نامعتبر/فاقد مجوز/تعارض و مرور فرم با داده ساختگی لازم است؛ screenshot یا build به‌تنهایی شاهد پذیرش نیست. storage آزمون از اتصال واقعی جدا گزارش شود.
