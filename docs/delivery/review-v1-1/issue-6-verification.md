## رفتار حاصل

گرید محصول اکنون اکشن «تنوع‌ها»، «قیمت و موجودی» و لینک جزئیات دارد. اکشن گرید فرم مشترک را در dialog باز می‌کند و تب‌های جزئیات همان component و use case و شناسه‌ها را مصرف می‌کنند. این dialog مدیریتی است؛ تصمیم صفحه مستقل PDP مشتری تغییر نکرده است.

مدیر می‌تواند از محورهای صریح دسته، ترکیب معتبر و SKU یکتا بسازد و برای فروشنده مجاز عرضه ثبت کند. قیمت و موجودی عرضه مستقل ویرایش می‌شوند. موجودی کل، رزروشده و قابل تخصیص کنار هم‌اند. وقفه فقط از فروشگاه خوانده می‌شود. قیمت ورودی وب تومان و مبلغ ذخیره/API ریال است.

حساب‌های ساختگی فروشنده از همان جدول User و عضویت سروری استفاده می‌کنند. در رابط مشترک فقط عرضه فروشگاه خود را می‌بینند/ویرایش می‌کنند؛ محتوای مشترک و ساخت تنوع مرکزی در اختیارشان نیست. عضویت با مجوزهای create/price/stock مستقل، برش محدود آزمون است و تکمیل نقش سفارشی/مدیریت عضویت #1 یا کل پنل فروشنده محسوب نمی‌شود.

## نتیجه اجرا

- `go test ./...` و `go vet ./...` موفق؛۵۶ تست و زیرتست موفق در مجموعه API. [خلاصه ماشین‌خوان](issue-6-checks.json) از خروجی JSON اجرای واقعی تولید شده است.
- `npm run lint` و `npm run build` بک‌آفیس موفق. هشدارهای قبلی bundle بزرگ و annotation وابستگی غیرمسدودکننده‌اند.
- Playwright CLI:۲۱/۲۱ بررسی موفق، بدون pageerror در اجرای نهایی. یک پاسخ409 عمداً با تغییر هم‌زمان واقعی API ایجاد شد؛ ادعای نبود network/console error نمی‌شود.
- مرورگر۱۴۴۰ و۳۹۰ پیکسل بررسی شد؛ صفحه و فرم overflow افقی ندارند، جدول عریض در محدوده خودش اسکرول افقی دارد.
- `go test -race` محلی اجرا نشد چون runtime ویندوز CGO/C compiler ندارد؛ workflow لینوکس CI آن را جدا اجرا می‌کند. نتیجه نهایی CI در PR و کامنت ایشو پیگیری شود.
- سه سناریوی [BDD](../../bdd/features/experiences/product-workspace.feature) با همان ACها ثبت شد؛ runner مستقل Gherkin اجرا نشده است.

در مرورگر، پیش از ارسال یک فرمان قیمت، یک درخواست API واقعی با نسخه فعلی ثبت شد؛ درخواست اولیه409 گرفت. فرم draft را حفظ و ثبت را تا «بازخوانی و بازبینی» غیرفعال کرد. سپس با نسخه تازه همان مقدار موردنظر ثبت شد؛ خطا صرفاً با mock ساخته نشده است.

## تکرار بررسی

پس از build وب، از `apps/api` یک fixture تازه اجرا کنید. اجرای موفق مرورگر داده را تغییر می‌دهد؛ برای تکرار، فقط سرویس آزمون خودتان را با داده تازه بالا بیاورید:

~~~powershell
$env:APP_ENV='test'
$env:PORT='8096'
$env:WEB_ROOT='../backoffice-web/build'
go run ./cmd/api
~~~

سپس از ریشه مخزن:

~~~powershell
npx --yes --package @playwright/cli playwright-cli -s=cherriva-products open http://127.0.0.1:8096/
npx --yes --package @playwright/cli playwright-cli -s=cherriva-products run-code --filename tests/e2e/product-workspace.cjs
~~~

حساب‌های ساختگی از دکمه‌های ورود انتخاب می‌شوند؛ کد آزمون فقط در local/test نمایش داده می‌شود. انتخاب فروشنده مسیر auth سطح seller را مصرف می‌کند؛ نشست بک‌آفیس در endpoint فروشنده و برعکس پذیرفته نمی‌شود.
