# پرامپت‌های آماده ورود داده کاتالوگ

## برای الیاس؛ ورود کامل در لوکال

```text
بسته docs/delivery/catalog-seed را در D:\Cherriva بخوان و snapshot واحد data/catalog/gooshishop-2026-11-22.json را در دیتابیس بررسی محلی چریوا وارد کن. فایل را با SHA-256 ثبت‌شده در manifest تطبیق بده و از ابزار موجود apps/api/cmd/catalog-import استفاده کن؛ به SQL Server مبدأ متصل نشو.

ابتدا dry-run را اجرا کن. از اتصال خصوصی REVIEW_DATABASE_URL همان محیط لوکال استفاده کن، migrationها را اعمال کن و workspace را با برنامه فعلی بالا بیاور. سپس با mode=review و apply و configure-home کل فایل را بدون limit-products وارد کن. تصاویر باید با checksum دریافت و در جدول رسانه مقصد ذخیره شوند. اگر conflict یا خطای تصویر بود، علت را برطرف کن؛ اطلاعات موجود را حذف یا با SQL مستقیم جایگزین نکن.

کاربران، رمزها، نقش‌ها، سفارش‌ها، موجودی کیف پول، دفتر مالی، بانک، پرداخت و ارسال فعلی را حفظ کن. بنرها و کمپین‌های گوشی‌شاپ را فعال نکن. پس از ورود، تکرار همان فرمان باید already_applied=true بدهد. خانه و چهار ریل، یک PLP از هر گروه اصلی، چند PDP دیجیتال و طلا، ویژگی کارت، breadcrumb، تنوع، قیمت و تصویر را بررسی کن؛ نمونه انتخاب و سبد را هم بررسی کن. پس از restart داده باید حفظ شود. نتیجه و محدودیت‌ها را بدون اطلاعات اتصال در گزارش ثبت کن و لینک محصول نمونه بده.
```

## برای پارسا؛ پس از انتشار نسخه جدید روی سرور بررسی

```text
طبق docs/delivery/catalog-seed/README.md، فایل data/catalog/gooshishop-2026-11-22.json و manifest همان revision را برای ورود کاتالوگ تست به محیط سرور بررسی چریوا استفاده کن. از ابزار catalog-import موجود در image جدید استفاده کن؛ اگر image قبلی است، ابتدا همین نسخه را طبق روال انتشار تیم آماده کن. دیتابیس مبدأ گوشی‌شاپ و هیچ اطلاعات کاربر/مالی از آن نیاز نیست.

هدف، دیتابیس همان برنامه سرورِ اعلام‌شده برای بررسی است. با DATABASE_URL تنظیم‌شده آن محیط، origin=live و بدون REVIEW_DATABASE_URL، SHA فایل، migrationها، فضای cache و فضای PostgreSQL را بررسی کن. ابتدا dry-run، سپس ورود کامل با -apply -configure-home و بدون limit-products انجام بده. تصاویر باید decode و با checksum وارد دیتابیس شوند. namespace ثابت gsp- است؛ داده موجود، هویت، بانک و دفتر مالی را بازنویسی نکن. اگر مشکل یا conflict بود، به‌جای حذف داده آن را حل و گزارش کن.

اجرای دوباره نباید داده تکراری بسازد. پس از restart، خانه، PLP، PDP، تنوع و قیمت، رسانه‌ها و انتخاب محصول تا سبد را روی همین محیط بررسی کن. بنر قدیمی گوشی‌شاپ و تنظیمات مالی/ارسال مبدأ را فعال نکن. خروجی گزارش شامل revision، شمارش واردشده، وضعیت retry/restart و URLهای نمونه باشد؛ credential یا connection string را ثبت نکن. این داده snapshot تست است و قیمت/موجودی زنده محسوب نمی‌شود.
```
