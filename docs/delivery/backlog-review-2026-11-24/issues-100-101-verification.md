# نتیجه #100 و #101

فرم آدرس، پروفایل دارای کد ملی و snapshot گیرنده تکمیل شدند. «نشانی کامل» بالاترین ردیف تمام‌عرض فرم است. SDK رسمی نشان، انتخاب pin، ذخیره مختصات و پیشنهاد نشانی قابل قبول/ویرایش آماده‌اند. بنا بر انتخاب صریح مالک **فعلاً اتصال آماده است و کلیدهای واقعی بعداً تنظیم می‌شوند**؛ نقشه حساب واقعی فعال یا مصرف آن تأییدشده نیست. ورود دستی مستقل از نقشه کار می‌کند.

## مرور کوتاه #96 تا #99

بستن هر چهار Issue و کامنت تکمیل با کامیت `35f9c59e9e3b11a7398d7f537451f60014859b36`، [گزارش قبلی](issues-96-99-verification.md) و [PR #106](https://github.com/MohamadParsa/marketplace/pull/106) تطبیق داده شد. کار آن agent دوباره پیاده نشد. تنها fixture نوشتن آدرس در اسکریپت مرورگر قبلی با الزامات تازه آدرس سازگار شد.

| AC04 — داده قدیمی/مودال/خطا | آدرس قدیمی قابل خواندن و تکمیل است؛ ویرایش آن به خود مشتری نسبت داده نمی‌شود؛ مرورگر تغییر سویچ، حفظ پیش‌نویس پس از خطا، Escape، cascade و عرض۳۹۰ را بررسی کرد |

دو ویرایش هم‌زمان با یک نسخه فقط یک نتیجه موفق می‌سازند و retry همان ورودی همان نتیجه را می‌دهد. اطلاعات تازه پروفایل در نشست موجود خوانده می‌شود.

| معیار | شاهد |

| AC02 — پاسخ دیررس | در مرورگر لغو شبکه عمداً نادیده گرفته شد تا پاسخ‌ها جابه‌جا برسند؛ پیشنهاد قدیمی جای پاسخ تازه را نگرفت و متن دستی خودکار تغییر نکرد |
| AC03 — خطا و fallback | خطای SDK، بدون کلید، رد geolocation، خطای provider و شهر ناشناخته آزمون شدند؛ فیلدهای دستی فعال ماندند؛ timeout و پاسخ نامعتبر آداپتر در Go آزمون شدند |
| AC04 — ساختگی/واقعی جدا | پروتکل HTTP نشان با سرور محلی و SDK رسمی با تایل/lookup ساختگی آزمون شدند؛ کلید/دامنه/تعرفه حساب واقعی پس از تنظیم مالک آزمون می‌شوند |

سمت سرور auth/surface، محدوده مختصات، داده اضافی/URL دلخواه، no-store، جغرافیای فعال، مخفی‌ماندن خطای خصوصی و سقف درخواست آزمون شده‌اند. شمارنده مصرف در این برش درون هر پردازش است؛ سقف قطعی هزینه باید از حساب سرویس اعمال شود.

## بررسی‌های اجراشده

- `go test -json ./...`: **۳۰۹ تست و زیرتست موفق**، بدون شکست. PostgreSQL آزمون schema مستقل و Redis آزمون مستقل بود. سه skip: دو harness دستی مرورگر و `TestCatalogSnapshotPostgresRoundTrip` که به opt-in/fixture واردسازی نیاز دارد. harness آدرس جداگانه با opt-in اجرا شد.
- `go vet ./...`: موفق.
- `npm run lint` و `npm run build` هر دو frontend: موفق؛ هشدار قدیمی اندازه chunk پنل مانع build نیست.
- Playwright: **۲۴ بررسی موفق**، بدون `pageerror`؛ خطاهای شبکه تزریقی عمداً بخشی از fallback هستند.
- Go race محلی/CI تازه اجرا نشده‌اند؛ نتیجه CI کار قبلی #96–99 به این کد نسبت داده نمی‌شود.
- `git diff --check`، لینک‌های نسبی، یکتایی شناسه‌های تازه و سازگاری index موفق بودند.

Go از `apps/api` و npm از پوشه همان app اجرا می‌شوند؛ ریشه مخزن `package.json` ندارد. [اسکریپت مرورگر](../../../tests/e2e/issues-100-101.cjs) با harness اختیاری `CHERRIVA_ADDRESS_BROWSER=1` روی پورت۵۱۹۸ اجرا می‌شود. دو مسیر فایل SDK در اسکریپت مربوط به runtime خصوصی‌اند؛ برای سیستم دیگر SDK رسمی pinned را از URLهای قرارداد دانلود و مسیرها را به فایل آزمایشی خود بدهید. هیچ کلید واقعی لازم نیست.

## نسخه محلی و حفاظت داده

دو frontend و API ساخته و migration عقب‌مانده۱۰ و جدید۱۱ روی همان دیتابیس بررسی محلی اعمال شدند. پیش/پس از شروع، hash و شمارش کاربران/رمزها/نقش‌ها/عضویت‌ها، سفارش‌ها، فروشگاه‌ها، دفتر، انتقال‌ها، واریزها و گردش کیف پول برابر ماندند. جدول جدید `commerce_credit_lots` مربوط به #97 ایجاد شد و **صفر رکورد** دارد. هیچ شارژ، پرداخت، سفارش یا آدرس آزمایشی در دیتابیس بررسی اصلی ساخته نشد؛ نوشتن‌های مرورگر حافظه‌ای و PostgreSQL آزمون در schema مستقل بودند. تست PostgreSQL کد ملی و آدرس را پس از ایجاد مجدد repository خواند.

اتصال دیتابیس، کلید سرویس و فایل‌های audit خصوصی در مخزن/گزارش نیستند. راه‌انداز با `REVIEW_DATABASE_URL` همان محیط خصوصی اجرا شد.

## باقی‌مانده خارج از دامنه فعلی

تنظیم حساب واقعی نشان، دامنه مجاز، کلید وب/سرویس، تعرفه/quota و آزمون نشانی واقعی پس از آن؛ این گام طبق پاسخ مالک به بعد واگذار شد. آدرس دستی به آن وابسته نیست. پوش/ادغام تغییرهای فعلی و انتشار لیارا انجام نشده‌اند.

در تست ویرایش سریع، callback انیمیشن Leaflet پس از بستن مودال خطای مرورگر می‌ساخت؛ حرکت برنامه‌ای بدون انیمیشن و توقف نقشه پیش از حذف، آن را رفع کرد. سناریوی کلیک/کشیدن pin و ویرایش/ذخیره سریع با SDK واقعی در۲۴بررسی نهایی بدون خطای runtime پاس شد. راه‌انداز محلی نیز پورت واقعی cluster خصوصی موجود را از فایل وضعیت می‌خواند تا شروع بدون env در این سیستم به پورت اشتباه متصل نشود.
