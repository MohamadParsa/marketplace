## #103 — فاصله‌ها و خوانایی

متن تزئینی و تکرار عنوان بالای PLP حذف شد؛ breadcrumb و h1/SEO حفظ‌اند. فاصله هدر، عنوان، زیرشاخه‌ها، کارت‌ها، گالری، خرید و جزئیات فشرده شد. مرتب‌سازی موبایل یک ردیف افقی قابل پیمایش کنار دکمه فیلتر است؛ radio بومی برای کیبورد/دسترس‌پذیری حفظ و فقط نمایش آن طبق تصمیم قبلی پنهان است. بازگشت focus پس از بستن فیلتر موبایل اصلاح شد. هدف لمس کنترل‌ها۴۴px باقی است.

بنر fallback در موبایل فشرده‌تر است. **تصویر بنر منتشرشده برش نمی‌خورد**: قاب دسکتاپ۱۶:۵ و موبایل۲:۳ با contain، محتوای تصویر فعلی را کامل حفظ می‌کند؛ کاهش ارتفاع فرم به معنای بریدن متن بنر نیست. بنر تصویری بلند همچنان بخش بزرگی از دید اول موبایل را می‌گیرد؛ برای کوتاه‌ترشدن آن باید خود asset موبایل با نسبت مناسب طراحی شود. در نمونه فعلی، دستکاری قیمت/موجودی/متن محصول یا بنر انجام نشده است.

## #104 — بارگذاری داده و تصویر

کارت، دسته‌ها و ریل‌های خانه، فیلتر/گرید PLP و گالری/اطلاعات/خرید اولیه PDP placeholder متناسب دارند. از LoadingPlaceholder/BusyRegion موجود استفاده شد؛ عملیات انتخاب و سبد همچنان overlay دارند. قاب تصویر، فضای خود را از پیش می‌گیرد؛ خطا و تصویر نداشته fallback دارند، تغییر src با frame تازه پاسخ دیررس تصویر قبلی را نشان نمی‌دهد. آغاز نمایش skeleton تصویر۱۲۰ms تأخیر دارد تا cache-hit سریع چشمک نسازد؛ shimmer در reduced-motion خاموش است. تصویر/سکشن fetch تازه و اعلان تکراری screen reader ایجاد نمی‌کند.

برای بنر و promo داده‌محور، کارت و گالری همان قاب مشترک به کار رفت. تنظیم دسته بنر و category_id ریل با قرارداد جدید هم‌قالب شد. ابعاد تصویر در slow-image ثابت ماند؛ error/retry، نتیجه خالی و برگشت سریع صفحه placeholder ماندگار نساختند. بلندی متن ناشناخته می‌تواند ارتفاع کل سند را تغییر دهد؛ ادعای صفرشدن همه جابه‌جایی‌ها وجود ندارد.

## #102 — قرارداد عمومی، بدون تعویض شناسه ذخیره‌شده

[قرارداد و تصمیم انتخاب‌شده](../../architecture/contracts/public-catalog-references.md). تنوع chr-v، عرضه chr-o و رسانه chr-m هستند؛ referenceهای محصول/دسته/خصوصیت/برند/فروشگاه هم هم‌قالب‌اند، در حالی که URL اصلی محصول chr-عدد و دسته slug باقی است. ورودی قدیم و جدید به همان موجودیت resolve می‌شوند. canonical بدون query انتخاب است و آدرس انتخاب قدیمی در HTML/SPA اصلاح می‌شود. نوع اشتباه، ورودی معیوب و انتخاب نامرتبط رد می‌شوند.

DTO/URL عمومی خانه/منو/PLP/PDP، selection، سبد، wishlist/recent، خرید و بنر پوشش دارند؛ store_ids ارسال و category_id بنر با سایر مراجع منطبق‌اند. متن انسانی، اعداد۶۴بیتی و اطلاعات مالی/کاربری از projection عبور می‌کنند و بازنویسی نمی‌شوند. API بک‌آفیس raw باقی است؛ این مرز داخلی عمدی است. namespace/envelope کش۷ است؛ TTL و invalidation و warmup startup قبلی حفظ‌اند. ETag از پاسخ نهایی صادر می‌شود و انتخاب قدیم/جدید نتیجه یکسان دارد.

هیچ اتصال به SQL Server مبدأ، migration تازه، بازنویسی PK/FK، تغییر seed/manifest یا بانک/دفتر/موجودی کیف پول انجام نشد. تست مالی/دوام در schema ایزوله PostgreSQL است؛ تست live review فقط سبد مهمان مستقل ساخت و اقلام آن را حذف کرد؛ سفارش، واریز یا پرداخت نساخت. توکن، رمز یا مجوز نیست.

## مشاهده و تکرار

از `D:\Cherriva` فرمان ` .\Start-Cherriva.ps1` اجرا شود؛ build آماده: `.\Start-Cherriva.ps1 -NoBuild`. [راهنمای کامل محلی](../../local-development.md). سایت http://localhost:5197 و پنل http://localhost:8098؛ نمونه http://localhost:5197/category/mobile و http://localhost:5197/product/chr-10082.

`go test ./...` و `go vet ./...` از apps/api؛ integration فقط با تنظیم خصوصی دیتابیس/Redis آزمون ایزوله. `npm run lint` و `npm run build` از apps/storefront-web. تست‌های CLI مرورگر با run-code --filename روی فایل‌های بالا و محیط محلی اجرا می‌شوند؛ تست خرید به پیش‌فرض فعال‌سازی **لوکالِ جدا و هنوز کامیت‌نشده** PDP مربوط است و نمی‌توان آن را به فلگ توقف نسخه پوش‌شده تعمیم داد. انتشار آن اصلاح در #105 باقی است. اسرار اتصال در این گزارش نیستند.

برای تکرار تست خرید روی commit سورسِ بدون override جدا، پیش از build سایت مقدار `VITE_PDP_ADD_TO_CART=true` تنظیم شود؛ اطلاعات اتصال یا رمز لازم برای این پرچم وجود ندارد.
