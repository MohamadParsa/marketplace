# تصمیم‌ها و سؤال‌های برنامه پنل

| شناسه | موضوع | وضعیت/تصمیم |
| --- | --- | --- |
| BOREF-Q01 | تغییر محور مصرف‌شده | حل‌شده با پاسخ مالک: preview اثر و تبدیل کنترل‌شده داده؛ جزئیات نگاشت در شروع #109 تحلیل می‌شوند. |
| BOREF-Q02 | مجوز دسته فروشگاه | حل‌شده: همه/فقط انتخابی، استثناها، زیرشاخه و deny مقدم؛ سازگاری فروشگاه قدیمی. |
| BOREF-Q03 | active محصول | حل‌شده: مستقل از انتشار؛ خرید تازه غیرفعال ممنوع و سابقه محفوظ. |
| BOREF-Q04 | رمز اولیه و نام قدیمی | حل‌شده: رمز موقت با تغییر اجباری؛ نام خانوادگی قدیمی حدس زده نشود. |
| BOREF-Q05 | واحدهای مجاز و ارث واحد | باز قبل از اجرای بخش تازه #117: فراتر از g/mm چه واحدهایی و آیا نزدیک‌ترین والد دخیل است؟ پیشنهاد فعلی دسته صریح سپس عمومی؛ بدون تصمیم، برچسب واحد ذخیره‌شده تغییر نکند. |
| BOREF-Q06 | رمز موقت و OTP | حل‌شده با پاسخ صریح همین نوبت: ورود با رمز موقت یا OTP ابتدا تعیین رمز شخصی؛ تا آن زمان بدون دسترسی عادی. reset ادمین هم flag را فعال و نشست‌های قبلی را باطل می‌کند. [قرارداد](../../architecture/contracts/user-management.md). |
| BOREF-Q07 | alias روش فروش قبل از انتخاب روش | طراحی قابل بررسی در #114: نمایش نام اصلی/حالت نقدی تا انتخاب روش پیشنهاد است؛ پس از انتخاب alias همان روش، StoreID ثابت و هویت مالی جداست. |

این سؤال‌ها مانع ثبت تسک یا بهبود مستقل فیلتر/فرم‌های روشن نیستند. قالب فنی کد chr خصوصیت و نگاشت conflictهای تبدیل نیز باید در طرح اجرایی همان کار ثبت شوند؛ تغییر مخرب PK/FK و سابقه از این برنامه مجاز نیست.

قالب فنی #110 اجرا شد: همان codec نوع a از ID و Code مستقل؛ تعریف ذخیره‌شده و روابط واردسازی محفوظ‌اند. [قرارداد](../../architecture/contracts/catalog-attributes.md#تکمیل-مرز-پنل-و-کد-چریوا--110). دستور تازه مالک پوش پس از اتمام را مجاز می‌کند؛ این تغییرِ سیاست تحویل از پذیرش سند و استقرار جداست.
