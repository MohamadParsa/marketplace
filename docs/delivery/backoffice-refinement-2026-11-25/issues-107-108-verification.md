# دامنه تحویل

۱۰۷ و۱۰۸ با دستور صریح مالک انتخاب شدند. فرم تجمیعی قابل مشاهده حذف و چهار موجودیت کاتالوگ از یک منوی والد باز/بسته‌شونده به صفحات اختصاصی می‌رسند. فرم دسته و UX انتساب خصوصیات، فیلترهای مستقل و علت قفل‌ها تکمیل می‌شوند؛ قوانین داده و مجوزهای فعلی حفظ‌اند. طرح A و نشان C همان مرجع قبلی است.

## تفکیک صفحه‌ها و مسیرهای قدیمی

| مسیر جاری | مسئولیت |
| --- | --- |
| `/categories` | فهرست، فیلتر ترکیبی، ایجاد/ویرایش دسته با درخت، آیکن، خصوصیات و مارکاپ |
| `/attributes` | تعریف مشترک خصوصیت در کتابخانه؛ مرجع chr قبلی #110 محفوظ |
| `/brands` | انتقال ایجاد/ویرایش پایه نام/فعال‌بودن و آیکن موجود به صفحه برند |
| `/products` | انتقال ایجاد/ویرایش محتوای موجود به فهرست محصول؛ تنوع/قیمت/موجودی و جزئیات قبلی محفوظ |
| `/home-settings` | چهار ریل ثابت خانه در بخش محتوا؛ لینک مدیریت بنر دسکتاپ/موبایل |
| `/home-catalog` | فقط redirect سازگار؛ query category/brand/product/create به همان فرم اختصاصی می‌رسد؛ بدون query به خانه |

ویرایشگر مشترک در `catalog-pages.tsx` reuse می‌شود، ولی صفحه تجمیعی یا تب تعویض موجودیت نداریم. انتقال فرم‌های موجود برند/محصول، نیاز وابستگی ناوبری #107 را پوشش می‌دهد؛ نام انگلیسی/شرح برند و فیلترهای تازه #115، Active مستقل و سایر تکمیل‌های #116 اجرا نشده و آن دو Issue باز می‌مانند. به‌جای انتظار آن‌ها، فرم پایه موجود بدون حذف قابلیت منتقل شد.

## دسته و خصوصیت

فیلترها AND هستند: نام فارسی، نام انگلیسی، انتشار، بایگانی، وجود خصوصیت/محور و والد/شاخه. والد می‌تواند فرزندان مستقیم، خود والد و زیرشاخه‌ها یا فقط ریشه‌ها را محدود کند. حالت پیش‌فرض بایگانی‌ها را پنهان می‌کند؛ انتخاب همه/بایگانی‌شده صریح است. انتخاب والد برای فیلتر، دسته بایگانی‌شده را هم پشتیبانی می‌کند؛ فرم ایجاد همچنان والد بایگانی‌شده انتخاب نمی‌کند.

گرید مشترک #81 شامل صفحه‌بندی۲۰/۵۰/۱۰۰، فیلترهای ستونی/مرتب‌سازی، خروجی Excel مجاز و اکشن ثابت است. تغییر فیلتر اختصاصی صفحه را بازنشانی می‌کند. فیلتر/paging در این برش روی workspace دریافتی در مرورگر است؛ pagination ایندکس‌دار SQL و کوچک‌کردن کل workspace ادعا نمی‌شود.

دیالوگ خصوصیات دو بخش مستقل «منتسب» و «قابل افزودن» دارد؛ قابل افزودن‌ها جست‌وجو و صفحه‌بندی می‌شوند. از تعریف مشترک انتخاب می‌شود و ارث خودکار والد نداریم. هر ردیف دلیل حذف‌ناپذیری، قفل محور، نوع غیرانتخابی یا مجوز را به متن قابل خواندن نشان می‌دهد. تعداد و پیوند کالاهای وابسته و لینک همه محصولات همان دسته موجود است.

تغییر محور دسته دارای محصول همچنان از این فرم ممنوع است و پیوند روشن به #109 دارد؛ آن تسک عملیات تبدیل را بعداً می‌سازد. حذف انتساب بدون مصرف و flags کارت/فیلتر/position آزادند. position همان یک عدد مشترک مدل فعلی است و ترتیب کوچک‌تر جلوتر، در subset هر نقش اعمال می‌شود؛ سه ترتیب مستقل تازه فرض نشده است. پیش‌نمایش زنده، عنوان/ترتیب سه نقش را نشان می‌دهد؛ پیش‌نمایش فقط عنوان و ترتیب نقش‌هاست؛ مقدار واقعی و سقف کارت در خروجی سایت از داده محصول و تنظیم فعلی گرفته می‌شود. کالای ساختگی برای preview ساخته نمی‌شود.

نسخه اصلی در dialog snapshot می‌شود؛ تغییر هم‌زمان هشدار و بارگیری صریح دارد. خطا/۴۰۹ draft را نگه می‌دارد. mutation با version و کلید تکرار ارسال می‌شود؛ الگوی سرور و invalidation موجود #41/#102 reuse شده است. آیکن و metadata/SEO/نام‌های دسته و tree فعلی حفظ‌اند؛ تغییر والد مصرف‌شده یا تبدیل داده در این کار انجام نمی‌شود.

## دسترسی

منوی والد با کیبورد و aria-expanded کار می‌کند، فرزند جاری مشخص و در موبایل داخل منوی موجود است. کاربران و نقش‌ها صفحات مستقل باقی‌اند. فروشنده فقط بخش محصولات/سفارش خودش را می‌بیند و deep-link دسته/برند/خانه او را به فهرست محصول می‌برد.

API هم سطح نشست را کنترل می‌کند: حتی حساب دارای نقش global عملیات و عضویت فروشگاه، از نشست seller نمی‌تواند catalog/attribute/category/homepage/settings نمایش یا انتشار/رد محصول را مستقیم اجرا کند؛ همان حساب با نشست مجاز بک‌آفیس مسیر قبلی را دارد. تغییر قیمت/موجودی و ثبت محتوای مجاز فروشنده از مسیرهای قبلی پابرجاست. این guard محدود، ممیزی جامع #71 نیست.

## نتیجه نهایی کنترل محلی

۳۳۲تست/زیرتست Go موفق،۴skip اختیاری و صفر شکست؛ PostgreSQL با schemaهای ایزوله و Redis فعال بودند. go vet و lint/build بک‌آفیس موفق؛ سورس storefront تغییر نکرده است. هشدار قبلی chunk بزرگ بک‌آفیس باقی است و وابستگی تازه اضافه نشده. race محلی اجرا نشده و نتیجه CI جدا ثبت می‌شود.

۳۷کنترل مرورگر موفق با صفر runtime pageerror: CRUD پایه در مسیرهای اختصاصی، لینک‌های قدیمی، فیلتر ترکیبی/شاخه/صفحه‌بندی، علت قفل و پیوند محصول، حفظ draft در۴۰۹، مصرف تعریف مشترک، flags و تازگی PLP، عدم ارث، readonly نقش viewer، چهار ریل و بنرها، کیبورد و موبایل. این تست‌ها روی حافظه ایزوله‌اند؛ سناریوی BDD فقط مستند است و runner مستقل ادعا نمی‌شود.

پس از restart نسخه اصلی در D:\Cherriva،۲۴بخش هویت/هش رمز/نقش/عضویت، سفارش، منابع اعتبار/دفتر/بانک و کاتالوگ/قیمت/موجودی/audit با baseline hash یکسان داشتند. startup warmup و Redis برقرار است؛ snapshot با SHA-256 manifest برابر و بدون تغییر باقی ماند. هیچ SQL مستقیم برای بازنویسی، حذف یا جایگزینی داده اجرا نشد.
