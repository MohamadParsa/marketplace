# نتیجه محلی #63

قلب ذخیره/حذف کنار گالری PDP، صفحه **علاقه‌مندی‌های من** و آیکن قلب/شمارنده کنار سبد خرید پیاده شد. لینک علاقه‌مندی در منوی پروفایل و صفحه حساب نیز هست. مسیر [فهرست محلی](http://localhost:5197/account/wishlist) و [محصول نمونه](http://localhost:5197/product/chr-10082) قابل بررسی‌اند. طرح A و رنگ چریوا حفظ شدند؛ dropdown جدید، خرید از کارت یا پنل مدیریتی برای فهرست خصوصی ساخته نشد.

مالک تأیید کرد مهمان پس از ورود ذخیره کند و محصول پنهان/حذف‌شده یک ردیف عمومی قابل حذف داشته باشد؛ صرف ناموجودی با پنهان‌شدن فرق دارد. [قرارداد](../../architecture/contracts/customer-wishlist.md) رفتار و API/حریم خصوصی را ثبت می‌کند. در زمان تحویل اولیه #63، تسک #64 شروع نشده بود؛ در نوبت بعدی طبق گزارش پیوندشده پایین تکمیل شد. #66 تحویل تحلیل قبلی است.

**۲۲۰تست/زیرتست Go موفق، یک skip اختیاری فایل بزرگ، بدون شکست؛ go vet موفق.** تست PG از schema موقت با cleanup استفاده کرد؛ داده اصلی را با SQL دست‌کاری نکرد. **۲۶کنترل مرورگر موفق، بدون runtime pageerror؛ build/lint storefront موفق.** خطای۵۰۳ عمداً برای مسیر شکست شبیه‌سازی شد؛ نبود خطای شبکه/console ادعا نمی‌شود. race محلی اجرا نشده و CI به علت نبود push اجرا نشد؛ موفقیت CI قدیمی شاهد این کد جدید نیست.

فرمان‌های بررسی: `go test -json ./...` با تنظیمات خصوصی تست PG/Redis موجود، `go vet ./...`؛ `npm run build` و `npm run lint` در storefront؛ `playwright-cli -s=cherriva-wishlist run-code --filename=tests/e2e/customer-wishlist.cjs`. محیط لازم در [راهنمای لوکال](../../local-development.md) آمده است؛ اطلاعات اتصال در گزارش نیست.

## داده و محدودیت تحویل

فهرست در payload پایدار workspace موجود ذخیره است و migration جدید لازم ندارد؛ یکتایی با همان Update سریال PG برقرار است. هیچ Price/Stock/Order/Wallet entry/Bank یا نقش برای این قابلیت تغییر نکرد؛ حفظ داده مالی/سفارش و عدم تغییر cache stamp در تست PG پوشش دارد. مرورگر فقط علاقه‌مندی دو حساب ساختگی را بررسی کرد و وضعیت قبلی bookmarkهای هدف را در پایان برگرداند؛ provider عادی سایت هنگام مهمان ممکن است سبد مهمان ایجاد کند. تست مالی/درگاه واقعی انجام نشد.

نسخه محلی از D:\Cherriva به‌روز و روی5197/8098 در حال اجراست. دستور مالک **فقط لوکال** است: هیچ commit/push/PR، کامنت، بستن Issue یا انتشار لیارا برای #63 انجام نشده؛ GitHub باز می‌ماند و done فقط وضعیت محلی قابلیت است. فایل‌های #66 و کار قبلی محفوظ‌اند؛ فایل‌های موقت `.playwright-cli` جزو تحویل نیستند.

## اصلاح ظاهری تأییدشده در نوبت #64

قلب کنار عکس به آیکن خالی/پُر بدون متن و کادر تبدیل شد؛ قلب هدر فقط برای واردشده نمایش دارد.۲۹کنترل رگرسیون به‌روز موفق بود؛ تصویرهای این گزارش با همین حالت جایگزین شدند. جزئیات و بررسی breadcrumb/RTL و history در [گزارش #64](issue-64-verification.md) است. تعداد۲۶کنترل و۲۲۰تست بالاتر سابقه تحویل اولیه #63 است؛ بررسی جاری۲۲۷Go و۲۹رگرسیون این قابلیت دارد.

مالک پس از تحویل محلی دستور داد «تغییرات را تا اینجا پوش کن» و سپس ادامه را خواست. محدودیت نگه‌داشت محلی برای **همین دسته #66/#63/#64 و اصلاحات قلب/breadcrumb** رفع شد؛ کامیت/پوش و PR/CI در حال انجام است. متن «فقط لوکال/بدون commit یا push» در بخش‌های قبلی تاریخچه تحویل اولیه است. وضعیت نهایی گیت/CI در همین بخش تکمیل خواهد شد. انتشار لیارا با پارسا و جداست؛ تغییرهای بعدی همچنان بدون دستور صریح تازه لوکال می‌مانند.
