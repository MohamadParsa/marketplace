# نتیجه محلی #64

نمایش موفق PDP برای کاربر واردشده ثبت می‌شود؛ بازدید دوباره همان ردیف را به ابتدا می‌آورد. فهرست [بازدیدهای اخیر](http://localhost:5197/account/recently-viewed) از حساب و منوی پروفایل در دسترس است:۵۰محصول از۳۰روز اخیر، تاریخ فارسی، حذف تکی و پاک‌کردن همه با فرم تأیید. ریل تازه PDP طبق انتخاب مالک اضافه نشد. محصول پنهان ردیف عمومی و قابل حذف، و محصول صرفاً ناموجود کارت عمومی دارد. [قرارداد](../../architecture/contracts/customer-recently-viewed.md) مرجع سیاست و جزئیات است.

ثبت تکراری/هم‌زمان user/product دوم نمی‌سازد؛ انتخاب تنوع همان PDP رویداد مشاهده دوباره نیست. ساعت برابر نیز ترتیب آخرین commit را حفظ می‌کند. مهمان ذخیره/ادغام ندارد؛ خانه/PLP/صفحه خطا/warmup ثبت نمی‌شوند. خطای ثبت سابقه به صفحه خطای محصول تبدیل نمی‌شود. این فهرست منبع خام Analytics نیست.

## اصلاحات همراه با درخواست تازه مالک

- کنار عکس محصول **فقط قلب خالی/پُر**، بدون متن و کادر/پس‌زمینه؛ label و tooltip دسترس‌پذیر و focus کیبورد و touch target۴۴پیکسل حفظ‌اند.
- آیکن علاقه‌مندی کنار سبد فقط وقتی token حساب وجود دارد نمایش داده می‌شود؛ مهمان آن را نمی‌بیند. رفتار مهمان قلب خود PDP همچنان ورود با بازگشت است.
- جداکننده breadcrumb از glyph قبلی به **`>`** در PLP/PDP و فرم‌های حساب/خرید تغییر کرد؛ جهت ltr و unicode-bidi:isolate از آینه‌شدن در RTL جلوگیری می‌کنند. مسیرهای دسته/برند و URL/SEO تغییر نکردند.

این تغییرهای UI دستور مستقیم همین نوبت‌اند؛ Issue جدید روی گیت ایجاد یا بازگشایی نشد. [شواهد به‌روز علاقه‌مندی](issue-63-verification.md) به این بازبینی متصل است.

## بررسی اجراشده و محدودیت

**۲۲۷تست/زیرتست Go موفق، یک skip اختیاری فایل بزرگ، بدون شکست؛ go vet و build/lint storefront موفق.** تست PG در schema موقت با cleanup است و ماندگاری ثبت، حذف فیزیکی پس از انقضا با ساعت کنترل‌شده، reopen و عدم تغییر نسل کش عمومی را پوشش می‌دهد. مرز۳۰روز/سقف۵۰ با ساعت کنترل‌شده تست شده‌اند؛ انتظار واقعی۳۰روز یا یک ساعت ادعا نمی‌شود. lifecycle startup/shutdown بدون Redis مستقلاً بررسی شد.

**۳۶کنترل مرورگر سابقه +۲۹کنترل رگرسیون علاقه‌مندی =۶۵کنترل موفق**؛ runtime pageerror وجود نداشت. داده عمومی کاتالوگ واقعی است؛ دو حساب ساختگی برای سابقه و دو حساب ساختگی برای رگرسیون قلب استفاده شدند. وضعیت hidden/pagination و خطاهای۴۰۴/۵۰۳ مرورگر fixture دارند؛ visibility و persistence واقعی در Go بررسی شدند. خطاهای شبکه شبیه‌سازی‌شده‌اند و نبود console/network error ادعا نمی‌شود. UI خطا/clear/cancel و جداسازی حساب‌ها بررسی شد؛ پاک‌کردن history، wishlist را حذف نکرد.

سابقه حساب‌های ساختگی این آزمون در پایان پاک و bookmarkهای هدف به حالت قبل برگشتند. در رگرسیون #63، ثبت history خارج دامنه intercept شد تا داده جانبی نسازد. سبد مهمان عادی سایت ممکن است ایجاد شود. هیچ کالا/قیمت/موجودی، بانک، دفتر مالی، سفارش، رمز یا نقش برای این قابلیت تغییر نکرد؛ حفظ مالی/سفارش/علاقه‌مندی و عدم invalidation کش در PG آزموده شد. migration جدید وجود ندارد و SQL Server مبدأ خوانده نشد.

پاک‌سازی فیزیکی runtime پایدار در startup و ساعتی اجرا می‌شود؛ نمایش موارد منقضی فوراً مسدود و حذف فیزیکی در سرویس سالم تا نوبت ساعتی ممکن است تأخیر داشته باشد. حذف از backupها و خاموش‌کردن دائمی tracking جزو این قابلیت نیستند؛ بازدید بعد از clear دوباره ثبت می‌شود.

فرمان‌ها: `go test -json ./...` با تنظیمات خصوصی تست PostgreSQL/Redis، `go vet ./...`، `npm run build`، `npm run lint` و Playwright CLI با دو فایل CJS بالا. race محلی اجرا نشده؛ CI تازه هم به علت نبود push اجرا نشده و CI قدیمی شاهد این تغییر نیست. اطلاعات اتصال/توکن در گزارش نیست.
