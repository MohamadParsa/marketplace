## خواسته تأییدشده مالک

لیست متعلق به کاربر؛ آیکن علاقه‌مندی کنار سکشن تصاویر PDP و دسترسی فهرست از آیکن قلب کنار سبد خرید. مهمان پس از ورود ذخیره کند؛ کالای پنهان/حذف‌شده ردیف عمومیِ قابل حذف و فاقد نام/عکس/قیمت/لینک داشته باشد.

## طراحی فنی پیشنهادی و داخل دامنه

پیشنهاد: ارتباط یکتای user/product و API idempotent افزودن/حذف، صفحه علاقه‌مندی در پروفایل. وضعیت قلب مستقل از تنوع انتخابی و با label/focus/بازخورد خطا؛ داده خصوصی از کش عمومی خارج باشد.

نوع کار: `implementation`. برای audit/design/analysis-first، گزارش و تصمیم پیش از اصلاح اجرایی است؛ کار بزرگ پس از تحلیل به زیرتسک قابل تحویل ریز شود. این بسته دامنه کل محصول یا مجوز سرویس بیرونی را گسترش نمی‌دهد.

## مرز مشترک و شرط شروع

مالک #63 را برای اجرای تک‌به‌تک انتخاب کرد؛ در نوبت جاری فقط همین قابلیت پیاده شد. وضعیت سند in-review و اجرای محلی done است؛ GitHub باز می‌ماند. دستور جاری حفظ لوکال است و بر روال تاریخی پوش/کامنت/بستن تقدم دارد. طرح **A — متعادل و شیک** و نشان C چریوا مرجع‌اند. تغییر پنل و API و storefront در محدوده همین قابلیت با هم دیده شود؛ قسمت نامرتبط با دلیل کنار گذاشته شود.

فرم بدون مجوز server-side کافی نیست: actor، store/user scope، version و idempotency متناسب حفظ شوند. loading/empty/error/forbidden/conflict و حفظ ورودی در خطا مشخص باشند؛ داده خصوصی وارد کش عمومی نشود و محتوای عمومی بعد از تغییر معتبر طبق سیاست کش تجدید شود. در UI کیبورد/RTL/موبایل و الگوی بارگذاری مشترک رعایت شوند؛ dropdown تازه فقط با نیاز صریح پذیرفته‌شده، مانند استان/شهر، مطرح شود.
