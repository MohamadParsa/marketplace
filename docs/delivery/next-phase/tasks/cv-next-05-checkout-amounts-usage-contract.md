# CV-NEXT-05 — قرارداد مبلغ سفارش، CreditUsage و DiscountUsage

Issue: [#66](https://github.com/MohamadParsa/marketplace/issues/66) · اساین: `eliassarband` · وضعیت GitHub: **open** · شروع اجرا: #66 به‌عنوان اولین نوبت انتخاب شد؛ تحلیل محلی با دستور ادامه مالک نهایی شد.

## مسئله و نتیجه بیزینسی

تخفیف، اعتبار و وجه باقی‌مانده بدون دوباره‌شماری قابل بازسازی باشند.

## خواسته تأییدشده مالک

کیف پول روش پرداخت نیست؛ اعتبار دلخواه کنار کد تخفیف و روش پرداخت مصرف می‌شود. نام‌های creditusage/discountusage پیشنهاد مالک‌اند.

## طراحی فنی پیشنهادی و داخل دامنه

پیشنهاد: مدل پیشنهادی usageهای متصل به سفارش/قلم/ارسال و منشأ/نسخه، وضعیت رزرو/قطعی/آزادسازی و money type صریح؛ مصرف اعتبار با تخفیف فرق دارد. جدول مثال مالی و قرارداد quote/صورتحساب/استرداد پیش از schema/کد تأیید شود؛ ledger موازی ساخته نشود.

نوع کار: `analysis-first`. برای audit/design/analysis-first، گزارش و تصمیم پیش از اصلاح اجرایی است؛ کار بزرگ پس از تحلیل به زیرتسک قابل تحویل ریز شود. این بسته دامنه کل محصول یا مجوز سرویس بیرونی را گسترش نمی‌دهد.

## مرز مشترک و شرط شروع

مالک #66 را همراه شش کار دیگر انتخاب و ترتیب را واگذار کرد؛ در این نوبت فقط **تحلیل #66** شروع شد. سند in-review و اجرای برش تحلیل done محلی است؛ تصمیم schema اجرایی به کار مربوط واگذار می‌شود. دستور جدید نگه‌داشت لوکال است: بدون push، کامنت یا بستن Issue روی گیت تا درخواست تازه مالک. طرح **A — متعادل و شیک** و نشان C چریوا مرجع‌اند. تغییر پنل و API و storefront در محدوده همین قابلیت با هم دیده شود؛ قسمت نامرتبط با دلیل کنار گذاشته شود.

فرم بدون مجوز server-side کافی نیست: actor، store/user scope، version و idempotency متناسب حفظ شوند. loading/empty/error/forbidden/conflict و حفظ ورودی در خطا مشخص باشند؛ داده خصوصی وارد کش عمومی نشود و محتوای عمومی بعد از تغییر معتبر طبق سیاست کش تجدید شود. در UI کیبورد/RTL/موبایل و الگوی بارگذاری مشترک رعایت شوند؛ dropdown تازه فقط با نیاز صریح پذیرفته‌شده، مانند استان/شهر، مطرح شود.

## شواهد پایان در مرحله اجرا

ACهای همین قابلیت به تست مناسب API/دامنه/مرورگر وصل شوند؛ fixture، اتصال محلی و provider واقعی جدا گزارش شوند. تکمیل سند، build یا اسکرین‌شات به‌تنهایی اثبات عملیات مالی/مجوز نیست. روال تاریخی پس از اجرای انتخاب‌شده، پوش/کامنت/بستن بود؛ دستور جاری مالک آن را تا اجازه صریح انتشار متوقف کرده است. در این نوبت گزارش/قرارداد فقط لوکال‌اند. انتشار لیارا همچنان با پارساست؛ در این نوبت Issue #66 روی GitHub باز می‌ماند.
