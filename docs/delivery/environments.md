# محیط‌های اجرایی

برای [تنظیمات درگاه #152](payment-gateway-settings-2026-11-28.md)، credential پذیرنده در دیتابیس همان محیط ذخیره می‌شود؛ `PAYMENT_GATEWAY_ENCRYPTION_KEY` کلید رمزنگاری پایدار و خارج دیتابیس است و همه پردازه‌های یک محیط باید مقدار یکسان داشته باشند. `PAYMENT_PUBLIC_BASE_URL` origin عمومی توسعه/استیج/پروداکشن را تعیین می‌کند؛ مسیر callback در کد ثابت است. تغییر محیط نیازمند تغییر کد نیست. مقدارهای نمونه و شیوه نگهداری کلید در گزارش تحویل و [env.example](../../apps/api/.env.example) ثبت‌اند؛ اجرای درگاه هنوز فعال نشده است.

این سند قرارداد نام‌گذاری و جداسازی محیط‌های مرحله ۰ است؛ انتخاب provider، دامنه و مقدار secret در آن انجام نمی‌شود.

| محیط | هدف | داده مجاز | منبع تنظیمات |
| --- | --- | --- | --- |
| `local` | توسعه روی دستگاه توسعه‌دهنده | داده ساختگی محلی و قابل reset | فایل `.env` محلی خارج از git |
| `test` | اجرای unit، integration و contract test | داده آزمون ایزوله و قابل بازسازی | secretهای CI و سرویس آزمون |
| `staging` | smoke test و بررسی پیش از انتشار | داده آزمون جدا از production | secretهای staging در مخزن secret |

قواعد مشترک:

- مقدار واقعی secret، token، connection string و داده شخصی در repository ذخیره نمی‌شود.
- متغیرهای محیطی فقط از `.env.example` مستندسازی می‌شوند و فایل `.env` در git نادیده گرفته شده است.
- اتصال واقعی پرداخت، پیامک و حمل تا انتخاب provider و تصمیم اجرایی جداگانه فعال نمی‌شود.
- migration فقط پس از انتخاب ابزار، schema تأییدشده و روش قفل اجرای هم‌زمان در محیط `test` و سپس `staging` فعال می‌شود.
