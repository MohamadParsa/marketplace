# کیفیت و کنترل‌های قابل ارزیابی

این سند پیشنهاد معیارهای پذیرش فنی برای بررسی است، نه انتخاب فناوری یا اعلام انطباق قانونی. اعداد عملکرد، دسترس‌پذیری سرویس و استاندارد هدف هنوز در Q-008 تعیین نشده‌اند. قواعد محصول در حوزه‌ها مرجعند؛ اینجا روش اثبات آن‌هاست.

| شناسه | کنترل مورد ارزیابی | شاهد پذیرش |
| --- | --- | --- |
| NFR-INDEX-001-Q01 | جداسازی مشتری/فروشگاه | دسترسی مستقیم با شناسه موجودیت دیگر هیچ داده غیرمجاز برنگرداند |
| NFR-INDEX-001-Q02 | پنهان‌بودن اطلاعات پیش از تأمین | پاسخ داده، export، cache، لاگ و پیام فروشنده فاقد نام/تلفن/آدرس ممنوع باشند |
| NFR-INDEX-001-Q03 | یک‌باربودن اثر مالی | تکرار callback/درخواست، قطع ارتباط و restart باعث شارژ/برداشت/refund مضاعف نشوند |
| NFR-INDEX-001-Q04 | صحت موجودی | رقابت برای آخرین واحد، حداکثر یک تخصیص معتبر ایجاد کند |
| NFR-INDEX-001-Q05 | رقابت لغو و ارسال | یک قلم دو نتیجه نهایی ناسازگار نگیرد؛ نقطه قطعی طبق [DOM-SHIPPING-001-R11](../domains/shipping/README.md) |
| NFR-INDEX-001-Q06 | ساعت مرجع | اعتبارسنجی با زمان سرور، countdown UI صرفاً نمایشی؛ تغییر ساعت دستگاه مهلت را تمدید نکند |
| NFR-INDEX-001-Q07 | محاسبات پول | بدون خطای اعشاری و با واحد/گردکردن مصوب Q-007؛ جمع اقلام و تخصیص‌ها قابل بازسازی باشد |
| NFR-INDEX-001-Q08 | استقلال اعلان | قطع پیامک نتیجه قطعی پرداخت یا ارسال را تغییر ندهد؛ شکست قابل پیگیری باشد |
| NFR-INDEX-001-Q09 | تاریخچه عملیات حساس | تغییر قانون، تعیین تکلیف، refund و تسویه با عامل، زمان، مرجع، علت و تغییر نتیجه ردیابی شوند |
| NFR-INDEX-001-Q10 | حفاظت در PWA | خروج/تغییر حساب، داده حساس کاربر قبل را در cache قابل دسترسی باقی نگذارد |
| NFR-INDEX-001-Q11 | محتوای پویا | توضیحات/معرفی نتواند اسکریپت اجرا کند؛ محدودیت فایل/HTML طبق Q-011 |
| NFR-INDEX-001-Q12 | ورود و OTP | عمر، نرخ تلاش و ارسال مجدد پس از تعیین سیاست قابل آزمون باشد؛ کد و داده محرمانه لاگ نشود |
| NFR-INDEX-001-Q13 | مودال و بازگشت | لینک مستقیم، refresh، فوکوس و بازگشت به وضعیت جست‌وجو آزموده شوند |
| NFR-INDEX-001-Q14 | سقف برداشت خودکار | چند درخواست هم‌زمان نتوانند سقف اجرای خودکار تعداد یا مبلغ در بازه مصوب را نقض کنند؛ موارد بیش از سقف به بررسی بک‌آفیس بروند؛ انتظار رزرو را حفظ و رد/شکست قطعی فقط یک بار وجه/ظرفیت را آزاد کند |
| NFR-INDEX-001-Q15 | نمایش تاریخ و منطقه زمانی | تاریخ یک رخداد در هر سه محیط شمسی و با منطقه زمانی مرجع نمایش داده شود؛ تبدیل نمایش نباید زمان واقعی انقضا یا ترتیب رخدادها را تغییر دهد |

هدف latency، حجم کاتالوگ/کاربران، مدت نگهداری سوابق مالی، پشتیبان‌گیری و بازیابی، الزامات قانونی و حریم خصوصی بازار ایران، مرورگر و سطح دسترس‌پذیری باید پیش از تعهد عملیاتی تعیین شوند. استفاده از PWA به تنهایی تأیید خرید آفلاین نیست.
