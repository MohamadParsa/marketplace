# مدیریت برند — #115

## قواعد تأییدشده

مسیر `/brands` زیر کاتالوگ، نام فارسی و انگلیسی، توضیحات، تصویر و وضعیت `active` را مدیریت می‌کند. وضعیت انتشار موازی ایجاد نمی‌شود. شناسه و اتصال محصول/سفارش با تغییر نام یا وضعیت عوض نمی‌شوند. طرح A و نشان C پابرجاست.

## قرارداد اجرایی

همان `POST /backoffice/commands` با actionهای `catalog.brand.create` و `catalog.brand.update` مصرف می‌شود؛ API CRUD دوم نداریم. `catalog.name` الزامی، حداکثر۱۶۰حرف؛ `english_name` اختیاری حداکثر۱۶۰ و `description` اختیاری حداکثر۴۰۰۰حرف است. `catalog.published` در DTO مشترک، همان Active برند است. رشته‌ها هنگام ذخیره trim می‌شوند. فیلدهای جدید در JSON قدیمیِ خالی حذف می‌شوند (`omitempty`)؛ ترجمه حدسی یا بازنویسی گروهی برندهای واردشده نداریم.

تفسیر فنی یکتایی: نام فارسی و نام انگلیسیِ غیرخالی پس از trim، یکسان‌سازی ي/ی و ك/ک و بدون حساسیت به بزرگی حروف، با سایر برندها تکراری نباشند. برندهای قدیمی هنگام شروع تغییر نمی‌کنند؛ تعارض در ذخیره اعلام می‌شود. نام و شناسه تصادفیِ برخوردکرده با409 رد می‌شوند. ویرایش به target و version فعلی نیاز دارد؛ نامعتبر400، نبود رکورد404، بی‌مجوز403 و نشست نامعتبر401 است. idempotency_key و audit همان pipeline تراکنشی موجود است؛ تکرار همان فرمان اثر دوباره ندارد. خطا پیش‌نویس فرم را حفظ می‌کند.

تصویر با [قرارداد موجود رسانه](catalog-icons.md) و endpointهای قبلی set/remove جداگانه ذخیره می‌شود؛ ابتدا اطلاعات برند ثبت و سپس «تصویر برند» روی ردیف انتخاب می‌شود. فایل نامعتبر تصویر قبلی را حذف نمی‌کند. برند غیرفعال هم می‌تواند تصویر آماده کند یا به پیش‌فرض برگردد؛ تصویرش تا فعال‌شدن عمومی نمی‌شود و این موضوع در دیالوگ توضیح داده می‌شود. مجوز set و remove در UI مستقل و در سرور دوباره کنترل می‌شود.

## نمایش و حفاظت داده

قبل از ذخیره، تعداد محصولات متصل و اثر وضعیت در فرم مشخص است. `validBrand` موجود، محصولات برند غیرفعال را از نمایش عمومی خارج می‌کند؛ وضعیت stored محصول، BrandID، SEO و snapshot سفارش دست‌نخورده می‌مانند. فعال‌سازی دوباره فقط همان قاعده نمایش را برمی‌گرداند. فرمان از repository موجود عبور می‌کند و revision/projection عمومی و کش وابسته تازه می‌شوند. داده افزایشی در workspace JSONB و تصویر در media موجود ذخیره می‌شود؛ migration DDL و اتصال مبدأ نداریم.

فیلتر مستقل نام فارسی، انگلیسی، وضعیت و داشتن تصویر به‌صورت AND روی workspace مجاز بارگذاری‌شده اعمال می‌شود؛ صفحه‌بندی۲۰/۵۰/۱۰۰، مرتب‌سازی/فیلترستون و Excel از DataTable مشترک #81 است. این مسیر ادعای صفحه‌بندی سرور برای میلیون‌ها برند ندارد؛ در صورت رشد داده، query مستقل نیازمند تسک بعدی است. اکشن‌ها در عرض محدود با scroll جدول قابل دسترسی‌اند؛ dropdown تازه نداریم.
