# آیکن دسته و برند — قرارداد برش آزمون

درخواست صریح مالک برای پیاده‌سازی [Issue #4](https://github.com/MohamadParsa/marketplace/issues/4) مجوز همین برش است. قاعده محصول، upload/preview/remove/fallback و مجوز کاتالوگ است؛ سیاست عددی زیر انتخاب فنی این پیاده‌سازی آزمون است و تأیید کل مشخصات یا سیاست نهایی production محسوب نمی‌شود.

## سیاست تصویر

- ورودی: PNG، JPEG و WebP واقعی؛ نام فایل و Content-Type ارسالی، مدرک صحت فایل نیستند.
- حداکثر فایل ورودی: ۱MiB یعنی۱٬۰۴۸٬۵۷۶ بایت. هر ضلع تصویر از۱ تا۱۰۲۴ پیکسل.
- سرور ابتدا ابعاد/قالب و سپس decode کامل را بررسی و نتیجه را PNG بازتولید می‌کند؛ metadata، نام مسیر و محتوای اضافی فایل ورودی در خروجی نگه‌داری نمی‌شوند. خروجی بازتولیدشده ممکن است از ورودی بزرگ‌تر باشد، اما ابعادش محدود است.
- SVG، GIF، HTML، فایل جعلی/خراب/بزرگ یا ابعاد خارج محدوده پذیرفته نمی‌شوند. گالری محصول و بنر، سیاست مستقل دارند.
- `GET /backoffice/workspace` مقدار `icon_policy {max_bytes,max_dimension,content_types}` را برمی‌گرداند؛ رابط محدودیت را از سرور می‌خواند.

## عملیات

| روش/مسیر | ورودی | نتیجه و مجوز |
| --- | --- | --- |
| `POST /backoffice/catalog/{kind}/{target}/icon` | multipart شامل یک `file`، یک `version` و یک `idempotency_key` | 204؛ همان سیاست مجوز کاتالوگ فعلی: مدیرکل و عملیات؛ کاربر جاری و فعال دوباره در سرور کنترل می‌شود |
| `POST /backoffice/commands` | `category.icon.remove` یا `brand.icon.remove`، `target`، `version`، `idempotency_key` | 204؛ حذف مرجع، نسخه تازه و audit اتمیک؛ بازگشت رابط به پیش‌فرض |
| `GET /catalog/icons/{id}` | شناسه غیرقابل تبدیل به مسیر فایل | PNG با nosniff/no-store؛ فقط وقتی به دسته غیرآرشیو یا برند فعال متصل باشد؛ ناموجود/بدون اتصال/حذف‌شده404 |

`kind` فقط `category` یا `brand` است. فیلدهای multipart اضافی و فایل/فیلد تکراری رد می‌شوند. تغییر فایل و اتصال به رکورد و audit در یک تراکنش repository انجام می‌شود؛ شکست نسخه/اعتبارسنجی فایل قبلی را حفظ می‌کند. ذخیره‌سازی باینری داخل adapter حافظه‌ای آزمون است و در workspace عمومی برنمی‌گردد. تصویر جایگزین‌شده بدون مرجع از حافظه وضعیت کنار گذاشته می‌شود.

شناسه فایل هنگام ثبت معتبر تولید می‌شود؛ پیش‌نمایش انتخاب‌شده در مرورگر object URL محلی است و تا ثبت، هیچ فایل عمومی یا draft در سرور ایجاد نمی‌کند. حذف و آپلود با کلید/بدنه یکسان retry امن دارند؛ استفاده همان کلید با محتوای متفاوت409 است.

## داده و نسخه

دسته و برند `icon_id?` و `version` دارند. نسخه صفر برای دسته‌های fixture قدیمی معتبر است؛ رکورد تازه از۱ آغاز می‌شود. هر ثبت/حذف آیکن نسخه را افزایش می‌دهد. نام دسته/برند مستقل از تصویر باقی می‌ماند. برندهای موجود در این برش سه رکورد ساختگی‌اند؛ ساخت/ویرایش کامل کاتالوگ برند، دامنه جداست و با تکمیل آیکن done نشده است.

## خطا و رابط

| HTTP | علت | رفتار |
| --- | --- | --- |
| 400 | فایل غیرواقعی/خراب، قالب/ابعاد نامجاز، بدنه ناقص/نامعتبر | خطای فرم؛ نگه‌داشتن تصویر ثبت‌شده و draft معتبر |
| 401/403 | نشست نامعتبر، کاربر غیرفعال یا فقدان مجوز | عدم تغییر داده؛ در401 درخواست ورود دوباره |
| 404 | مرجع پیدا نشد یا تصویر قابل نمایش عمومی نیست | پیام قابل فهم یا fallback تصویر با حفظ نام |
| 409 | نسخه کهنه، هدف غیرفعال/آرشیو یا کلید متعارض | بدون overwrite؛ فرم و انتخاب نگه داشته و بازخوانی/بررسی دوباره لازم است |
| 413 | حجم بیش از محدوده | انتخاب فایل کوچک‌تر؛ فایل قبلی حفظ شود |

فهرست دسته‌ها و صفحه برندها از component مشترک تصویر استفاده می‌کنند: نبود/حذف/خطای دریافت به SVG داخلی با نام قابل دسترس برمی‌گردد. فرم مشترکِ دارای پیش‌نمایش در موبایل و دسکتاپ استفاده می‌شود. برای نقش فقط مشاهده، دکمه ویرایش غیرفعال است و درخواست مستقیم سرور هم رد می‌شود. این برش، نقش‌های سفارشی Issue#1 را پیاده‌سازی نمی‌کند و از رجیستری مجوز فعلی استفاده می‌کند.

## پذیرش و مرز

نگاشت AC و شواهد در [گزارش Issue#4](../../delivery/review-v1-1/issue-4-verification.md) است. فایل و تغییرات با restart نسخه آزمون پاک می‌شوند؛ persistence، فضای شیء واقعی، CDN و فعال‌سازی روی محیط اصلی خارج این برش هستند. مسیر استقرار خودکار با انتشار PR یکی نیست؛ انتشار اصلی پذیرش جدا دارد.

## افزوده ذخیره پایدار رسانه — ۲۰۲۶-۱۱-۲۲

[بسته ورود کاتالوگ](../../delivery/catalog-seed/README.md) و migration `000004-catalog-media`، باینری PNG را در PostgreSQL از JSON workspace جدا می‌کنند. snapshot کاتالوگ فقط مرجع `stored` دارد؛ سرویس پس از کنترل همان دسترسی قبلی، فایل را از مخزن می‌خواند. داده inline قبلی سازگار می‌ماند و در نوشتن بعدی به‌صورت اتمیک منتقل می‌شود. URL و بدنه API عمومی تغییر نمی‌کنند؛ workspace HTTP همچنان رسانه خصوصی را حذف می‌کند. این افزوده به‌تنهایی ادعای CDN/object storage یا استقرار عمومی نیست.
