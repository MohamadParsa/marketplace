# قرارداد پیشنهادی ارسال OTP با REST کاوه‌نگار

## هدف و طرف‌ها

این سند برداشت مستنداتی از [راهنمای REST کاوه‌نگار](https://kavenegar.com/rest.html) در تاریخ ۲۰۲۶-۱۱-۲۱ است. مصرف‌کننده، adapter اعلان OTP در API بازارگاه است و ارائه‌دهنده، سرویس REST کاوه‌نگار. adapter پیاده شده، اما اتصال واقعی فقط با تنظیم secret و template محیطی فعال می‌شود؛ انتخاب نهایی provider و مجوز اتصال عملیاتی هنوز ثبت نشده است.

## عملیات و دسترسی

برای OTP، متد `Lookup` مناسب‌تر از پیامک عادی است:

`https://api.kavenegar.com/v1/{API-KEY}/verify/lookup.json`

پارامترهای `receptor`، `token` و `template` اجباری‌اند؛ `token2`، `token3` و سایر tokenها اختیاری‌اند. `type` به‌صورت پیش‌فرض `sms` است. الگو باید پیش‌تر در پنل کاوه‌نگار تعریف و تأیید شده باشد؛ متن الگو نمونه‌ای مانند `کد ورود شما %token است` دارد. API-Key فقط در secret manager/تنظیمات امن adapter نگهداری می‌شود و هرگز در log، DTO، پاسخ API یا سند نمونه نمی‌آید.

## مرجع schema

مرجع بیرونی، راهنمای REST کاوه‌نگار است؛ این جدول فقط نگاشت مورد نیاز بازارگاه را ثبت می‌کند.

| ورودی / خروجی | فیلد | نوع و قالب | الزامی / nullable | محدودیت / معنا |
| --- | --- | --- | --- | --- |
| ورودی | `receptor` | string؛ شماره نرمال‌شده | الزامی | برای شماره بین‌المللی طبق راهنما با `00` و کد کشور |
| ورودی | `token` | string | الزامی | بدون فاصله؛ حداکثر ۱۰۰ نویسه؛ مقدار OTP کوتاه و ساختگی در آزمون |
| ورودی | `template` | string | الزامی | نام الگوی تأییدشده در پنل provider |
| خروجی | `return.status` / `return.message` | integer / string | provider | `200` به‌معنای پذیرش درخواست است، نه تحویل قطعی به گیرنده |
| خروجی | `entries[].messageid` | integer | provider | شناسه پیام برای پیگیری وضعیت |
| خروجی | `entries[].status` / `statustext` | integer / string | provider | وضعیت ارسال؛ متن خام OTP از پاسخ داخلی به مصرف‌کننده برنمی‌گردد |
| خروجی | `entries[].date` | Unix time | provider | زمان provider؛ تبدیل به زمان داخلی فقط با قرارداد زمان انجام شود |

فرمت JSON در adapter مرجع است؛ راهنما XML را نیز با تغییر پسوند ممکن می‌داند، اما بازارگاه در این برش XML را مصرف نمی‌کند.

## خطاها

| شناسه خطا | شرط وقوع | پاسخ / وضعیت | رفتار مصرف‌کننده |
| --- | --- | --- | --- |
| `400`, `406` | پارامتر ناقص یا اجباری خالی | خطای provider | retry خودکار نشود؛ خطای داخلی عمومی ثبت شود |
| `403` | API-Key نامعتبر | خطای پیکربندی | alert عملیاتی؛ secret در log نیاید |
| `411` | گیرنده نامعتبر | خطای داده | OTP مصرف نشود و خطای اعتبارسنجی عمومی برگردد |
| `418` | اعتبار حساب کافی نیست | خطای حساب provider | توقف retry و alert عملیاتی |
| `424` | template پیدا نشد/تأیید نشده | خطای پیکربندی | توقف retry تا اصلاح template |
| `429`, `451` | محدودیت IP یا نرخ فراخوانی | خطای موقت/محدودیت | طبق backoff و سقف داخلی؛ کد OTP دوباره در log نیاید |
| `409` | server provider موقتاً پاسخ‌گو نیست | خطای موقت | retry محدود با idempotency داخلی و بدون ارسال تکراری ناخواسته |

کدهای provider نباید مستقیماً به کاربر نمایش داده شوند. مهلت، single-use و سقف تلاش OTP در قرارداد هویت بازارگاه باقی می‌ماند و با وضعیت پیامک provider جایگزین نمی‌شود.

## قواعد ارتباط

درخواست فقط از adapter سمت سرور و روی HTTPS ارسال شود. timeout، retry و dedup باید در adapter نهایی شوند؛ درخواست تکراری نباید challenge جدید یا ارسال دوباره ناخواسته بسازد. `messageid` برای مشاهده وضعیت قابل نگهداری است، ولی کد OTP و API-Key هرگز ذخیره یا audit نمی‌شوند. قیمت/تعرفه و موجودی اعتبار provider بخشی از منطق دامنه نیست.

## سازگاری

هر تغییر provider باید پشت `OTPNotifier` بماند و قرارداد HTTP بازارگاه را تغییر ندهد. نام template، API-Key، IP مجاز و تنظیمات حساب، configuration محیط هستند و از fixture استنباط نمی‌شوند.

## نمونه و پذیرش

نمونه درخواست ساختگی:

```text
POST https://api.kavenegar.com/v1/{API-KEY}/verify/lookup.json
receptor=09000000001&token=123456&template=marketplace_login
```

پذیرش adapter: پاسخ `200` و `messageid` معتبر، خطای template/API-Key بدون افشای secret، timeout با retry محدود، و عدم مشاهده OTP خام در log/DTO. آزمون provider واقعی نیازمند API-Key، template تأییدشده و تصمیم مالک برای اتصال بیرونی است؛ در این مخزن اجرا نشده است.

## پرسش‌ها و تصمیم‌ها

- انتخاب کاوه‌نگار به‌عنوان provider عملیاتی، template نهایی، خط مبدا، IP allowlist، timeout/retry و بودجه هنوز تأیید نشده‌اند. adapter با `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` فعال می‌شود؛ در نبود هرکدام notifier حافظه‌ای/خطای پیکربندی استفاده می‌شود.
- تا تصویب این موارد، `local/test` از notifier حافظه‌ای استفاده می‌کند و بازیابی رمز از مسیر ادمین انجام می‌شود؛ بازیابی ایمیلی فعال نیست.
