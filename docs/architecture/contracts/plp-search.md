پاسخ‌های مالک CHQ-09 را فقط برای تجمیع PLP و R2-Q08 را فقط برای انتشار/متای دسته حل می‌کنند. فرمول طلا، مهاجرت محور فعال و جزئیات robots محصول از این پاسخ نتیجه نمی‌شوند.

## داده و فرم پنل

مرجع نوع‌های واقعی: [Go](../../../apps/api/internal/domain/catalog/catalog.go)، [CatalogInput](../../../apps/api/internal/application/backoffice/homepage.go) و [TypeScript](../../../apps/backoffice-web/src/shared/types.ts).

دسته همان Name فارسی، EnglishName، Description و Published را با `seo{meta_title,meta_keywords,meta_description}` تکمیل می‌کند. SEO یک شیء اختیاری در فرمان است: نبود آن مقادیر قبلی را حفظ می‌کند، ارسال شیء خالی پاک‌کردن متاها و استفاده از fallback است. ویرایش محتوا والد/آیکن/binding را بازنویسی نمی‌کند؛ تغییر والد گره موجود در این برش همچنان بسته است. فرم نام/محتوا/SEO و مسیر درخت را نشان می‌دهد. انتشار مجوز جدا و همه تغییرات همان version، idempotency و audit موجود را دارند.

حدود فنی همین برش: عنوان متا تا۱۶۰، keywords تا۵۰۰ و توضیح متا تا۴۰۰ نویسه؛ نام‌ها تا۱۶۰ و توضیح ساده همان۴۰۰۰. متن plain است و در HTML escape می‌شود؛ این قرارداد انتخاب HTML غنی محصول نیست. metadata خالی، نشت draft را مجاز نمی‌کند.

مقادیر خصوصیات غیرمحور از همان فرم محصول قابل ثبت‌اند تا کارت/فیلتر به داده مدیریت‌شده وصل شود. `catalog.attributes` اختیاری است؛ نبودش داده قبلی را حفظ می‌کند، آرایه خالی آن را پاک می‌کند. شناسه باید صریحاً به دسته محصول منتسب باشد، تکراری/ناشناخته رد می‌شود، enum از گزینه معتبر، number متناهی و مقدار متن حداکثر۱۶۰ نویسه است. مقدارهای محصول موجود برای سازگاری حفظ می‌شوند؛ محور و قیمت از Variant/Offer می‌آیند و مقدار محور همان تنوع بر مقدار عمومی اولویت دارد. ویرایش محتوای محصولِ منتشرشده ناموجود، انتشارش را خاموش نمی‌کند؛ حداقل قابل خرید هنگام ورود به وضعیت منتشرشده کنترل می‌شود.

فرم کتابخانه/انتساب و سقف کارت موجود از #5 مصرف می‌شود؛ کنترل‌های رابط مجوز عملیات قابل انتساب را رعایت می‌کنند و سرور در تراکنش دوباره اختیار کاربر جاری را می‌سنجد. فرم/مدل/آزمون موازی برای #24 ساخته نمی‌شود.

## API عمومی و query

- `GET /storefront/catalog`: فهرست دسته، جست‌وجو و تخفیف ویژه از یک query engine مشترک.
- `GET /storefront/suggestions?q=...`: حداکثر۶ محصول و۴ دسته مجاز برای popup؛ کد/شماره/اطلاعات حساب ندارد.
- در سطح وب storefront: `GET /category/{id}`، `/search` و `/offers` همان build React را با متای دسته در **HTML اولیه** برمی‌گردانند. HTML و API یک قرارداد فهرست را مصرف می‌کنند؛ پنل خصوصی workspace مصرف‌کننده عمومی نیست.

| پارامتر | قرارداد |
| --- | --- |
| `category` | شناسه دسته قابل نمایش؛ ناشناخته/پنهان404؛ نبود آن جست‌وجوی عمومی است |
| `q` | تا۸۰ نویسه؛ تطبیق همه کلمات به شکل substring روی نام فارسی/انگلیسی محصول. نرمال‌سازی ی/ک عربی، ارقام فارسی/عربی، اعراب، فاصله/نیم‌فاصله و حروف بزرگ/کوچک |
| `sort` | فقط default، newest، price-asc، price-desc و best-selling؛ ناموجودها در انتها، قیمت بدون ارسال و از عرضه نقدی معتبر |
| `in_stock` | صفر یا۱؛ مقدار۱ فقط عرضه قابل خرید را نگه می‌دارد |
| `min_price` / `max_price` | عدد صحیح ریال طبق قرارداد فعلی API؛ UI تومان و تبدیل دقیق دارد. منفی، بازه معکوس یا بیشتر از سقف Offer رد می‌شود |
| `attr.{id}` | فهرست مقادیر؛ OR داخل یک ویژگی و AND بین ویژگی‌ها. فقط binding دارای filter در دسته انتخاب‌شده مجاز؛ فیلترهای والد به فرزند ارث نمی‌رسند |
| `page` / `page_size` | پیش‌فرض۱/۲۰؛ page از۱تا۱۰٬۰۰۰ و page_size از۱تا۴۰. صفحه پس از انتها محصولات خالی با total معتبر دارد |
| `special` | صفر یا۱؛ مسیر `/offers` مقدار۱ را الزامی می‌کند؛ فقط تخفیف واقعی عرضه نماینده |

پارامتر ناشناخته، مقدار تکراری نامجاز، enum نامعتبر، ویژگی دسته دیگر یا attr بدون دسته با400 رد می‌شود. query بیش از۴KiB و escape نامعتبر رد می‌شود؛ JSON و HTML خطا وضعیت HTTP واقعی دارند. API فاقد مجوز پنل401/403، تعارض409 و خطای مخزن503 است؛ خطا داده قبلی را تغییر نمی‌دهد.

## انتخاب محصول، تنوع و ویژگی کارت

فقط محصول منتشرشده در شاخه قابل نمایش و برند فعال در صورت انتساب، وارد projection می‌شود. وجود موجودی از انتشار مستقل است: محصول ناموجود در PLP باقی می‌ماند، `available:false`، `price:null` و بدون Offer خرید؛ خانه همچنان ناموجود را نشان نمی‌دهد.

فیلترها به **همان تنوع** تطبیق می‌خورند؛ رنگ یک تنوع با گارانتی تنوع دیگر ترکیب نمی‌شود. بین عرضه‌های قابل خریدِ تنوع‌های منطبق، قیمت نقدی نهاییِ کمتر، تأمین سریع‌تر و سپس شناسه ثابت انتخاب می‌شود. بازه قیمت روی همین عرضه‌ها اعمال می‌شود و کالای گران‌تر را به ناموجود مصنوعی تبدیل نمی‌کند؛ اگر هیچ عرضه‌ای در بازه نبود، آن کالا از نتیجه همان فیلتر حذف می‌شود. تخفیف ویژه فقط به قیمت قبل‌تخفیف عرضه نماینده تکیه دارد؛ موتور تخفیف/کمیسیون/طلا اجرا نشده است.

ویژگی‌های کارت از binding همان دسته محصول، با ترتیب position و شناسه ثابت، مقدار معتبر موجود و سقف DisplaySettings می‌آیند. انتخاب محور به‌خودی‌خود نمایش کارت را فعال نمی‌کند. گزینه‌های فیلتر از محصولات مجاز همان دسته و عبارت جست‌وجو استخراج می‌شوند؛ شمارش ساختگی نمایش داده نمی‌شود. تعریف ویژگی مشترک است، انتسابش مستقل است.

CreatedAt برای محصول جدید از ساعت سرور ثبت می‌شود. برای داده قبلی، audit ایجاد معتبر مصرف می‌شود؛ بدون زمان واقعی، صفرزمان و شناسه ثابت جایگزین است و تاریخ تاریخی اختراع نمی‌شود. گزینه newest سنجه فروش/بازدید ندارد.

## رابط، امنیت و کش

هدر و کارت با خانه مشترک‌اند. popup دارای debounce۲۵۰ms، لغو و کنترل پاسخ قدیمی، combobox/listbox، کلیدهای جهت/Enter/Escape و صفحه نتایج است. فیلتر/sort/page/query در URL هستند؛ Refresh و Back انتخاب و موقعیت پیمایش را بازمی‌گردانند. موبایل فیلترها را در پنجره دارای قفل تمرکز/پیمایش و بستن با Escape دارد. بارگذاری/بدون نتیجه/دسته ناموجود/فیلتر نامعتبر/خطای سرور و retry مجزا هستند.

DTO عمومی فقط شناسه/نام/لینک، ویژگی‌های نمایش، قیمت نقدی مجاز، navigation، فیلتر و SEO دارد؛ موجودی دقیق، اطلاعات کاربر/نشانی، audit، hash، مالی و باینری ندارد. پاسخ JSON عمومی ETag از بدنه و `Cache-Control: public, no-cache` دارد؛ تغییر مؤثر قیمت/موجودی/انتشار/binding/SEO/سقف کارت در درخواست بعد بازخوانی می‌شود. HTML نیز no-cache است؛ اطلاعات خصوصی همچنان no-store.

## انتخاب فنی و محدودیت اجرا

این مرحله جست‌وجوی ساده Go روی snapshot پایدار repository موجود دارد؛ در حالت PostgreSQL داده از همان adapter بررسی خوانده می‌شود. query ورودی به SQL/الگوی اجرایی تبدیل نمی‌شود و موتور خارجی/فروش/بازدید ساختگی اضافه نشده است. این scan روی aggregate کوچک فعلی، ادعای query/index بهینه SQL یا مقیاس بزرگ تولید نیست؛ جایگزینی آینده read-model بدون تغییر این قرارداد ممکن است.

`WEB_SURFACE=storefront` همراه `WEB_ROOT=../storefront-web/build`، مسیرهای HTML متادیتا را فعال می‌کند؛ پنل با سطح backoffice و build خودش جدا اجرا می‌شود. دو فرایند محلی یک PostgreSQL بررسی را مصرف می‌کنند. در Vite توسعه، API proxy کار می‌کند؛ بررسی SEO HTML اولیه با وب‌سرور Go و build واقعی انجام می‌شود، نه تگ افزوده‌شده صرفاً با JS. robots عمومی نسخه بررسی هنوز noindex/nofollow است؛ فعال‌سازی محیط عمومی و backup/restore در گیت #30/#12 باقی‌اند. گارد local/test مخزن بررسی برداشته نشده است.
