# قراردادهای ارتباطی

مرجع فعلی [تعاملات منطقی](interactions.md) است؛ عملیات و شکست‌های لازم را به قابلیت‌ها و حوزه‌ها وصل می‌کند. هیچ URL، پروتکل یا قرارداد نهایی برای تولید کد انتخاب نشده است.

پس از حل موانع همان مسیر، قرارداد executable با schema منتخب اضافه شود؛ اگر HTTP انتخاب شد OpenAPI و اگر پیام انتخاب شد schema مناسب آن. تعریف نوع فیلد، nullability، خطا، نسخه، احراز هویت، pagination و نمونه‌ها در schema مرجع نگهداری شود؛ جدول موازی با تعریف متفاوت ایجاد نشود.

## وضعیت انتخاب اتصال‌ها

وضعیت زیر به‌صراحت توسط مالک محصول در ۲۰۲۶-۱۱-۰۷ اعلام شده است؛ انتخاب ارائه‌دهنده به مرحله بعد موکول می‌شود.

| اتصال | وضعیت | آنچه پس از انتخاب تکمیل می‌شود |
| --- | --- | --- |
| درگاه نقدی | انتخاب‌نشده | تأیید/استعلام پرداخت، شناسایی مبدأ کارت، روش برداشت و refund و محدودیت‌های واقعی |
| BNPL | انتخاب‌نشده | قرارداد پرداخت اعتباری، تأیید/ابطال و refund کامل/جزئی |
| پیامک | انتخاب‌نشده | ارسال OTP/اعلان، وضعیت تحویل، محدودیت‌ها و سیاست retry |

قرارداد بیرونی فقط از مستندات رسمی ارائه‌دهنده واقعی استخراج شود. نبود انتخاب، مجوز فرض‌کردن قابلیت‌هایی مثل refund جزئی یا API برداشت برای هر درگاه نیست؛ این قابلیت‌ها باید پیش از اتصال مسیر مربوط احراز شوند. قواعد محصول مستقل از انتخاب ارائه‌دهنده مستند می‌مانند.

روش‌های حمل در حوزه ارسال تعریف شده‌اند؛ اتصال مستقیم به API شرکت حمل در دامنه فعلی الزام نشده است.
