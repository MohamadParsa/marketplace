# قرارداد شناسه عمومی — #102

## قواعد تأییدشده

مالک قالب توکن مستقل `chr-v-…` برای تنوع، `chr-o-…` برای عرضه و `chr-m-…` برای رسانه را انتخاب کرد. URL محصول `chr-عدد` و slug دسته طبق #42 حفظ می‌شوند. لینک و سبد قبلی باید همان عرضه را حفظ کنند؛ تغییر PK/FK، seed، manifest، سفارش یا دفتر مالی مجاز نیست. اجرای همین قابلیت در۲۰۲۶-۱۱-۲۴ انتخاب شد؛ انتشار کد همچنان منتظر دستور جداست.

## راه‌حل فنی اجراشده

توکن از `chr-{kind}-{Base64URL بدون padding از کل شناسه داخلی}` ساخته می‌شود؛ به قالب عددی مبدأ وابسته نیست. تبدیل injective است، جدول نگاشت و migration ندارد و با restart ثابت می‌ماند. **Base64 رمزنگاری نیست؛ این شناسه مجوز دسترسی نیست.** متن انسانی، مبلغ، شماره سفارش، کاربر، اطلاعات بانک و شناسه‌های مالی بازنویسی نمی‌شوند. پیشوندهای `chr-{kind}-` در مرز عمومی برای همین قرارداد رزرو هستند؛ فرمان ساخت شناسه داخلی از ورودی مشتری استفاده نمی‌کند.

| kind | موجودیت |
| --- | --- |
| v | تنوع |
| o | عرضه |
| m | رسانه کاتالوگ/بنر؛ مجوز هر endpoint جدا باقی است |
| p | reference محصول در DTO؛ URL اصلی محصول همچنان public_code است |
| c | reference دسته در DTO؛ URL اصلی دسته همچنان slug است |
| a | خصوصیت و کد فنی خصوصیت واردشده در خروجی عمومی |
| b | برند |
| s | فروشگاه |

نمونه ساختگی: `variant-1` → `chr-v-dmFyaWFudC0x`. الگوریتم و کنترل دقیق ورودی در [codec](../../../apps/api/internal/application/backoffice/public_references.go)، فهرست فیلدهای DTO و URL در [مرز HTTP](../../../apps/api/internal/transport/http/catalog_references.go) مرجع اجرایی‌اند؛ شناسه‌های شناخته‌شده در DTO و آرایه محدودیت دسته/فروشگاه با همین projection صادر می‌شوند. جایگزینی متنی کور روی متن/HTML یا دیتابیس وجود ندارد. دقت اعداد JSON از جمله مقدار صحیح۶۴بیتی با `UseNumber` حفظ می‌شود.

## ورودی، مجوز و سازگاری

- مسیر PDP، selection، wishlist و recently viewed توکن p و شناسه/کد قدیمی را می‌پذیرند. query تنوع/عرضه، فیلتر خصوصیت و دسته و ورودی سبد قبل از اعتبارسنجی به شناسه اصلی resolve می‌شوند.
- فرم عرضه واقعی، موجودی، ارتباط محصول/تنوع/عرضه و مالکیت حساب همان کنترل‌های قبلی را اجرا می‌کنند. توکن معتبرِ متعلق به محصول دیگر انتخاب مجاز نمی‌سازد. داده خصوصی هرگز وارد کش عمومی نمی‌شود.
- توکن نوع اشتباه، نامتعارف/ناقص، محتوای غیر UTF-8، شناسه بیش از۱۲۸بایت، slash یا NUL رد می‌شود. حداکثر توکن query عمومی۲۵۶کاراکتر است؛ شناسه decode‌شده همان حد قدیمی۱۲۸بایت را دارد. تکرار query و زوج کلید قدیمی/جدید یک فروشگاه در انتخاب ارسال رد می‌شود.
- normalize ورودی قبل از idempotency سرویس انجام می‌شود؛ retry همان عملیات با شناسه قدیمی/جدید نتیجه یکسان دارد. سبد، wishlist و سابقه همچنان شناسه داخلی را ذخیره می‌کنند.
- بارگذاری مستقیم لینک انتخاب قدیمی به مسیر/انتخاب جدید redirect۳۰۱ می‌شود؛ SPA بدون fetch اضافه، آدرس را replace می‌کند. canonical همیشه URL پایه محصول و بدون query انتخاب است. خطای انتخاب نباید با انتخاب پیش‌فرض پنهان شود.
- رسانه عمومی با توکن m و مسیر قدیمی کار می‌کند؛ attachment/publication همان مجوز قبلی است. داده باینری و checksum عوض نمی‌شوند؛ مراجع ذخیره‌شده داخلی raw باقی‌اند. مرز خصوصیات BO API بعداً در #110 طبق [قرارداد خصوصیات](catalog-attributes.md#تکمیل-مرز-پنل-و-کد-چریوا--110) تکمیل شد.
- category_id بنر داده‌محور و ریل خانه و store_ids روش ارسال با مراجع سایر DTOها هم‌قالب‌اند؛ تولید URL تازه در JSON و HTML پیش‌نمایش بنر هم پوشش داده شده است.

## کش و خطا

Projection روی پاسخ عمومیِ cache hit و miss یکسان اعمال می‌شود و خواندن اضافه دیتابیس ایجاد نمی‌کند. ETag از بدنه نهایی عمومی محاسبه می‌شود. namespace/envelope کش در تحویل #102 به `public:v7` رفت تا URL مشتق قدیمی دوباره استفاده نشود؛ TTL، invalidation و warmup راه‌اندازی #41 برقرارند. کش داخلیِ DTO عمومی whitelist قبلی را نگه می‌دارد؛ داده مالی/کاربر وارد آن نمی‌شود.

ورودی مرجع نامعتبر۴۰۰، موجودیت منتشرنشده/ناشناخته۴۰۴ و انتخاب خرید ناموجود۴۰۹ طبق قراردادهای قبلی است؛ خطا no-store است. پاسخ سبد، سفارش، wishlist/recent و محتوای نظر/پرسش خصوصی در کش عمومی نمی‌روند. معنای خطاهای مالی تغییر نکرده است.

## پذیرش و محدودیت انتشار

تست‌های codec، دقت پول، نوع اشتباه، query، سبد و retry قدیمی/جدید، wishlist/recent، مجوز رسانه و restart PostgreSQL در [تست دامنه](../../../apps/api/internal/application/backoffice/public_references_test.go)، [تست HTTP](../../../apps/api/internal/transport/http/catalog_references_test.go) و [پذیرش یکپارچه](../../../apps/api/internal/bootstrap/public_references_test.go) آمده‌اند. [گزارش سه تسک و تصاویر](../../delivery/backlog-review-2026-11-24/issues-102-103-104-verification.md).

این قرارداد API سرویس‌های داخلی را به پذیرش توکن عمومی تغییر نمی‌دهد؛ resolver در مرز HTTP است و کد داخلی باید همچنان شناسه داخلی بفرستد. اتصال SQL Server مبدأ، بازنویسی snapshot و مهاجرت داده در این تحویل انجام نشده‌اند. تأیید کل سند و انتشار محیط عمومی از انتخاب اجرای این تسک نتیجه نمی‌شود.

تکمیل #116، namespace/envelope را برای فیلد فعال‌بودن محصول به `public:v8` ارتقا می‌دهد؛ [قرارداد محصول](product-management.md). TTL، invalidation و warmup تغییری نکرده‌اند.
