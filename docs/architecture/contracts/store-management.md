# مدیریت فروشگاه — #113

## قواعد تأییدشده

فروشگاه از حساب کاربر مستقل است. نام، توضیح، ایمیل، وضعیت، تصویر، استان/شهر/نشانی/کدپستی، تلفن ثابت و موبایل قابل مدیریت‌اند. اعضا و نقش فروشگاهی واقعی نمایش داده می‌شوند؛ انتساب عضویت و نقش از فرم کاربران انجام می‌شود. وقفه تأمین، شناسه/مالک، مدل کاتالوگ و سیاست انتشار فعلی محفوظ‌اند. مجوز دسته و نام/روش فروش فروشگاه متعلق به #114 است.

## اجرای فعلی

مسیر پنل `/stores` مستقل است. نام اجباری و سایر فیلدهای تازه اختیاری‌اند؛ وجود استان، شهر معتبر فعال همان استان را لازم می‌کند. نشانی یا کدپستی بدون استان پذیرفته نمی‌شود. شهر قدیمی بدون استان فقط بدون تغییر حفظ می‌شود؛ استان حدس زده نمی‌شود. تغییر استان در فرم، شهر را پاک می‌کند.

| API | ورودی/رفتار |
| --- | --- |
| `POST /backoffice/stores/query` | `filter: {id,name,active,province,city,member,page,size}`؛ page صفرمبنا، size پیش‌فرض۲۰، حداکثر۱۰۰؛ active خالی/true/false |
| `POST /backoffice/stores/save` | `id,version,name,city,active,profile` و `Idempotency-Key`؛ id خالی برای ساخت، active و version صریح الزامی |
| `POST /backoffice/stores/export` | همان فیلتر و ids اختیاری؛ تمام نتایج فیلتر یا اشتراک ردیف‌های انتخابی؛ سقف۱۰هزار و مجوز Excel مستقل |
| `GET /backoffice/stores/{id}/image` | تصویر خصوصی احراز هویت‌شده، PNG و no-store |
| `POST /backoffice/stores/{id}/image` | multipart فقط file و version؛ Idempotency-Key؛ تصویر جدید بدون ذخیره متن فرم هم ممکن است |
| `DELETE /backoffice/stores/{id}/image` | version صریح و Idempotency-Key؛ بازگشت به تصویر پیش‌فرض |

profile شامل `description,email,province,address,postal_code,phone,mobile` است؛ image_id، مالک، وقفه و مدل از این ورودی قابل تزریق نیستند. فیلد ناشناخته رد می‌شود. نام حداکثر۱۶۰، توضیح۴۰۰۰، نشانی۱۵۰۰ کاراکتر؛ ایمیل normalize و اعتبارسنجی می‌شود، موبایل مطابق حساب ایرانی، تلفن ثابت۸تا۱۵رقم با + اختیاری و کدپستی۱۰رقم. محدودیت تصویر از normalizer مشترک: PNG/JPEG/WebP، ورودی حداکثر۱MiB، هر ضلع حداکثر۱۰۲۴؛ decode/reencode و حذف metadata؛ تصویر نامعتبر تصویر قبلی را از بین نمی‌برد.

## مجوز و حریم داده

- `stores.read` برای فهرست، پروفایل و تصویر؛ `stores.write` برای متن/وضعیت؛ `stores.media.write` برای تصویر؛ `stores.members.read` برای اعضا و فیلتر عضو. ادمین و عملیات این مجوزهای پیش‌فرض را دارند؛ نقش سفارشی قابل انتساب است. پوسته عمومی پنل مانند سایر فرم‌ها `workspace.read` نیز نیاز دارد.
- اعضا فقط نام، شناسه، وضعیت و نام نقشِ همان فروشگاه دارند. لینک فرم کاربر فقط با مجوز مشاهده کاربران/مالی نمایش داده می‌شود؛ credential یا کد ملی وارد DTO و export نمی‌شود.
- profile در workspace فاقد stores.read، workspace فروشنده، workspace محصول، projection عمومی و Redis عمومی حذف می‌شود. برای تصویر فروشگاه URL عمومی افزوده نشده است.
- نسخه نامنطبق۴۰۹، مجوز ناکافی۴۰۳، نشست نامعتبر۴۰۱، ورودی نامعتبر۴۰۰، رکورد ناموجود۴۰۴ و فایل بزرگ۴۱۳ است. خطای فرم draft را حفظ می‌کند.

## ذخیره و مرز فنی

فیلدها افزایشی و در JSONB موجود `review_workspace` ذخیره می‌شوند؛ به DDL یا backfill جدید نیازی نیست. تصویر در جدول موجود `catalog_media` ذخیره و با مرجع خصوصی متصل است. تراکنش موجود، نسخه/idempotency/audit را همراه داده ذخیره می‌کند. retry همان key و payload اثر دوباره ندارد؛ اگر بعداً ویرایش معتبری انجام شده باشد، retry پاسخ جاری رکورد را می‌دهد. payload متفاوت با همان key تعارض است.

صفحه‌بندی و فیلتر در سرور انجام می‌شود، اما مخزن کنونی snapshot کامل workspace را می‌خواند؛ ادعای query ایندکس‌شده یا مقیاس تولید نداریم. ساخت فروشگاه تازه، مجوز یا مالک فرضی و اتصال خودکار کاربر نمی‌سازد. داده legacy و تاریخچه مالی بازنویسی نمی‌شوند.
