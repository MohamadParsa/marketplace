# حساب و هویت

## قواعد تأییدشده

| شناسه | قاعده |
| --- | --- |
| DOM-IDENTITY-001-R01 | ورود مشتری با شماره تلفن و کد یک‌بارمصرف انجام می‌شود. |
| DOM-IDENTITY-001-R02 | نام، نام خانوادگی و آدرس در اولین خرید تکمیل و برای خریدهای بعدی ذخیره می‌شوند؛ ورودهای بعدی نیازمند ورود دوباره این اطلاعات نیستند. |
| DOM-IDENTITY-001-R03 | مشتری پیش از ادامه خرید باید وارد شود؛ جست‌وجو و ساخت سبد مهمان ممکن است. |
| DOM-IDENTITY-001-R04 | فروشنده توسط بک‌آفیس ایجاد می‌شود؛ ثبت‌نام آزاد فروشنده در دامنه فعلی نیست. |
| DOM-IDENTITY-001-R05 | مشتری می‌تواند چند آدرس ذخیره کند؛ برای هر خرید، یک آدرس مشترک برای تمام سفارش‌های فروشگاهی همان خرید انتخاب می‌شود. |
| DOM-IDENTITY-001-R06 | فعلاً هر فروشگاه یک حساب کاربری دارد؛ تیم چندکاربره و نقش‌های داخلی فروشگاه در دامنه فعلی نیستند. |
| DOM-IDENTITY-001-R07 | ورود فروشنده نیز با شماره تلفن و کد یک‌بارمصرف انجام می‌شود. |
| DOM-IDENTITY-001-R08 | ورود بک‌آفیس با شماره تلفن و کد یک‌بارمصرف است؛ ورود موفق تنها هویت را تأیید می‌کند و دسترسی عملیاتی تابع نقش و مجوز کاربر داخلی است. |
| DOM-IDENTITY-001-R09 | اطلاعات آدرس شامل استان، شهر، نشانی کامل، کدپستی، نام گیرنده و شماره تماس گیرنده است. گیرنده می‌تواند با صاحب حساب متفاوت باشد؛ اطلاعات پروفایل صاحب حساب با مشخصات گیرنده جایگزین نمی‌شود. |

## طراحی لازم برای بررسی

شماره تلفن باید به قالب واحد تبدیل شود؛ OTP محدودیت تلاش، عمر و ارسال مجدد داشته باشد. مقادیر این محدودیت‌ها و تغییر شماره در Q-016 باز هستند؛ روش ورود هر سه محیط قطعی است و مدیریت نقش کاربران داخلی در Q-004 تکمیل می‌شود. نام و آدرس به تنهایی عامل ورود نیستند.

داده مشتری در پروفایل با داده مقصد ثبت‌شده سفارش یکی نیست. پیشنهاد: ویرایش دفترچه آدرس روی سفارش پرداخت‌شده اثر نگذارد. چندآدرسی طبق R05 تأیید شده است؛ فیلدهای آدرس و گیرنده طبق R09 قطعی‌اند؛ اعتبارسنجی و جزئیات فرم در قرارداد اجرایی مشخص شوند. شماره گیرنده عامل ورود نیست و OTP ورود به شماره حساب مربوط است؛ نمایش نام/تلفن گیرنده به فروشنده تابع همان محدودیت تأمین حوزه سفارش است.

## پذیرش

- DOM-IDENTITY-001-AC01: مشتری جدید پس از تأیید شماره برای اولین خرید اطلاعات لازم را تکمیل کند؛ مشتری قبلی اطلاعات ذخیره‌شده را ببیند.
- DOM-IDENTITY-001-AC02: شکست ورود سبد مهمان را پاک نکند.
- DOM-IDENTITY-001-AC03: کاربر بدون مجوز بک‌آفیس نتواند فروشگاه ایجاد کند.
- DOM-IDENTITY-001-AC04: مشتری چند آدرس ذخیره‌شده داشته باشد و برای یک خرید چندفروشگاهی فقط یک مقصد مشترک انتخاب کند.
- DOM-IDENTITY-001-AC05: برای یک فروشگاه امکان افزودن حساب دوم یا تعریف تیم داخلی عرضه نشود.

- DOM-IDENTITY-001-AC06: فروشنده تعریف‌شده بتواند با تأیید کد یک‌بارمصرف شماره حساب خودش وارد شود؛ تأیید شماره ثبت‌نشده به‌تنهایی حساب فروشگاه جدید ایجاد نکند.

- DOM-IDENTITY-001-AC07: کاربر داخلی مجاز با OTP وارد شود ولی فقط عملیات نقش‌هایش را انجام دهد؛ تأیید شماره بدون دسترسی داخلی، مجوز بک‌آفیس نسازد.

- DOM-IDENTITY-001-AC08: مشتری بتواند آدرسی با نام/شماره گیرنده متفاوت ثبت و در خرید انتخاب کند؛ هویت ورود صاحب حساب تغییر نکند و اطلاعات گیرنده پیش از تأیید مجاز تأمین برای فروشنده افشا نشود.
